Why it matters

Defenders need enough code literacy to assess telemetry purpose, minimization, and endpoint controls. Minification/obfuscation raises review cost; it does not make data collection self-justifying.

Strict scope

Use only a supplied synthetic snippet or code you authored for local AbuseGuard. Do not fetch, execute, instrument, decrypt, or reverse real vendor scripts; do not use tokens, proprietary assets, or techniques intended to evade a third-party defense.

Format before interpretation

Pretty-print/minify formatting changes layout, not behavior. Rename local variables in notes, preserve original hash/version, and avoid running unknown code. Formatter output can hide malicious behavior if you execute it blindly.

Browser debugger on owned code

Use Sources pretty-print, breakpoint on learner-authored function, step over/into, and inspect only synthetic values. Set a precise question: “where is capability value read?” Stop when source-to-local-request path is documented.

AST view

An abstract syntax tree represents calls, literals, member access, functions, and control flow. AST Explorer is useful for local/synthetic code to distinguish string literal, property read, and call expression; it is a code representation, not automatic intent analysis.

Trace source → transformation → sink

const p = navigator.language; const body = JSON.stringify({ schema: 1, language: p }); fetch("/telemetry", { method: "POST", body });

Document source (navigator.language), transformation (object/JSON), sink (fetch body), endpoint, method, schema, consent, validation, and retention. Do not treat a hashed value as automatically anonymous.

Local request boundary

For owned local endpoint, inspect request schema/response in DevTools and server test logs. Server must authenticate/authorize where relevant, validate size/types, rate limit, redact logs, and reject unexpected origins/fields. Network panel proves browser attempted a request, not that server stored it safely.

Purpose and minimization

State first-party purpose, user notice/consent model, fields, retention, access, and deletion policy. Prefer a capability boolean over raw high-entropy fingerprint field when it meets the purpose.

Safety and limits

Static/dynamic analysis can miss feature flags, server behavior, generated code, and environment differences. Never inspect real vendor code for this curriculum. Debugger/AST artifacts may contain URLs/data; sanitize before sharing.

Defensive scenarios

Minified local probe

Trigger: unreadable variable names. Artifact: formatted owned snippet. Observation: one navigator read. Reasoning: trace to local body. Limit: formatting does not prove purpose.

Unexpected telemetry key

Trigger: server reject. Artifact: schema failure. Observation: client version mismatch. Reasoning: update/version policy. Limit: mismatch is not hostile.

Hashed field request

Trigger: hash added. Artifact: data-flow note. Observation: stable correlation possible. Reasoning: privacy review. Limit: hash is not automatically anonymous.

Endpoint error

Trigger: local fetch failure. Artifact: sanitized network/test record. Observation: CSP/network policy. Reasoning: validate config. Limit: not automation proof.
