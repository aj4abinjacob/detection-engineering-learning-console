Practical field guide · Evidence discipline

A traffic shape is evidence, not intent.

Detection engineering is strongest when it separates observed facts, bounded inferences, and verified labels—especially when a bot and a power user look alike.

01 · Purpose

Intent is not present in a log line

A request stream records what a system observed at one point. Calling it “malicious bot” without conditions converts uncertainty into an operational error.

FACT

Direct observation

Timestamp, route, status, bytes, trusted context.

INFERENCE

Conditional meaning

“Consistent with automation” plus alternatives.

LABEL

External adjudication

Verified abuse/fraud/authorized test outcome.

ACTION

Proportional response

Friction/review depends on confidence and harm.

02 · Evidence ladder

Fact“42 requests in 60s from trusted edge-derived key.”
→
Inference“High velocity; compatible with automation.”
→
Label“Verified test account / confirmed abuse.”

Do not silently turn an inference into a label. Record label source, adjudicator/time, and coverage limitations.

03 · Request-time facts

Facts include normalized method/route, status, duration, bounded bytes, authenticated state, trusted proxy-derived network context, protocol version at observation point, and sequence timing. “User is a bot,” raw IP reputation, or client header style are not direct facts about intent. Facts can still be wrong due to clock, proxy, parser, or instrumentation defects.

04 · Inference language

Use conditional claims: “pattern is consistent with scripted traversal,” “requires additional context,” “confidence increases if verified outcome follows.” State alternatives, observation point, and missing data. Multiple correlated signals are not automatically independent evidence; avoid multiplying confidence because several fields derive from one client/library/proxy behavior.

05 · Labels arrive later

Labels can come from authorized test fixtures, account recovery, chargeback, content investigation, support review, or policy adjudication. They can be incomplete, delayed, and biased. Keep labels outside request-controlled inputs, protect them from training/feedback leakage, and measure false-positive/false-negative uncertainty where possible.

07 · Context that earns confidence

Join trusted account/tenant state, explicit partner/test allowlists, request outcomes, resource effect, historical baselines, and delayed verified results. Every join has privacy/access/retention implications. A shared IP, VPN, CDN, proxy, or mobile carrier changes the meaning of network grouping.

08 · Decision policy

Use low-cost responses for weak ambiguous evidence (observe, gentle quota, offer supported API); raise friction or review only as impact/confidence justify; reserve hard action for verified/policy-defined conditions with rollback/appeal. Evaluate policy by protected harm and legitimate-user impact, not alert count alone.

09 · Safety

No client self-labelingExperiment labels, fraud verdicts, and allowlist decisions live in server-controlled synthetic fixtures. Never add a request header or parameter that declares a client “normal”/“abusive,” and never test against public users.

10 · Four defensive readings

PAGINATION

Fast catalog traversal

Trigger: high pages/min. Artifact: route/time series. Observation: breadth/low dwell. Reasoning: automation hypothesis. False-positive boundary: assistive/research/partner path; use quotas/API before ban.

LOGIN

Failure burst

Trigger: elevated failures. Artifact: account/source matrix. Observation: fan-out. Reasoning: stuffing-compatible. False-positive boundary: outage/password manager; inspect system health/delayed success.

API

Uniform request intervals

Trigger: regular timing. Artifact: interval summary. Observation: low variance. Reasoning: scheduled client-compatible. False-positive boundary: authorized integration; check contract/key.

ACCOUNT

New-account cluster

Trigger: shared attributes. Artifact: synthetic registration cohort. Observation: low conversion. Reasoning: fake-account-compatible. False-positive boundary: event/campus onboarding; defer label until outcome.
