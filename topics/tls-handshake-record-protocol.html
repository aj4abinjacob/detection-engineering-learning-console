TLS deeply

Mark the encryption boundary before interpreting TLS.

TLS 1.3 handshake derives keys and authenticates; record protocol carries protected content. ClientHello and ServerHello are visible, later handshake messages are encrypted.

Why it matters

TLS evidence is positioned evidence. A passive trace can show handshake metadata but cannot convert encrypted application bytes into HTTP meaning; a terminator and origin see different facts.

A compatibility ChangeCipherSpec record can appear and is ignored by TLS 1.3 peers. HelloRetryRequest, client authentication, resumption, post-handshake messages, and 0-RTT change the observed flight, so annotate the messages actually present instead of forcing every trace into this baseline.

Record protocol

TLSPlaintext header = content_type (1) | legacy_record_version (2) | length (2)
payload length       = unsigned 16-bit length; validate before slicing
protected record     = outer application_data | ciphertext-and-tag
inner plaintext      = content | inner content type | optional zero padding

Before keys exist, a record can carry plaintext handshake bytes such as ClientHello. After ServerHello, TLS 1.3 normally makes the outer record type application_data; the authenticated inner content type says whether the recovered content is handshake, alert, or application data. One handshake message can cross records, several can share a record, and one HTTP message can cross many TLS records.

Key schedule

HKDF derives handshake/application traffic secrets from PSK if any, ephemeral exchange, and transcript hashes. Captured traffic alone is not plaintext access; ephemeral exchange provides forward secrecy when used correctly.

Exact encryption boundary

Conventional TLS 1.3 exposes ClientHello and ServerHello. After ServerHello, Certificate and Finished are encrypted. With ECH, a visible ClientHelloOuter can carry an encrypted ClientHelloInner, so an observer does not automatically see the private SNI or ALPN. Client, server, and an authorized TLS terminator can see plaintext at their boundary; a passive PCAP alone cannot.

0-RTT caveat

Resumption may send early data before handshake completion. It has replay risk; accept only replay-safe/idempotent operations under explicit server policy. Capability does not prove acceptance or abuse.

Safety and limits

Use supplied sanitized PCAP or learner-owned loopback/AbuseGuard only. Do not capture others, export keys, or retain sensitive payloads. Loss, offload, middleboxes, resumption, and capture point change traces.

Detection scenarios

Handshake succeeds, app fails

TLS success does not prove HTTP authorization or origin processing.

Certificate absent in trace

Its TLS 1.3 handshake record is encrypted after ServerHello.

0-RTT review

Assess replay policy and method semantics, not an early-data verdict.

Client metadata rule

ClientHello correlation is low-confidence, not identity.

Saved-evidence drills

1. Flight diagram

Save artifacts/tls/tls-handshake.md from memory, then reconcile it against an authorized sanitized trace. For every packet, record frame number, direction, outer record type, handshake message when visible, and why the payload is or is not readable.

  • Mark ServerHello boundary.
  • Name CertificateVerify and Finished semantics.
  • Account for retransmission, coalescing, or compatibility CCS instead of silently discarding it.

2. Visibility matrix

Save tls-visibility.md for client, observer, terminator, origin.

  • Include unsupported inference.
  • Include cert visibility.

3. Record annotation

With Wireshark or TShark available, read—not live-capture—a supplied or learner-owned loopback trace and save a reproducible packet index:

mkdir -p artifacts/tls
tshark -r fixtures/tls13-loopback.pcapng -Y tls \
  -T fields -e frame.number -e ip.src -e ip.dst -e _ws.col.Info \
  > artifacts/tls/tls-frames.tsv

If TShark is unavailable, export the same four columns from Wireshark. Save record-annotation.md beside the TSV and identify what extra endpoint evidence would be required to interpret encrypted bytes.

  • Separate records/handshakes.
  • State no plaintext recovered.
  • Record capture point, tool version, authorization, and fixture hash.
