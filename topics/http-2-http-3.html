Practical field guide · Modern HTTP

Separate application streams from transport reality.

HTTP/2 multiplexes binary streams over TCP; HTTP/3 maps HTTP to QUIC over UDP. They improve concurrency and change what passive observers can see.

03 · HTTP/2

RFC 9113 uses binary frames and numbered bidirectional streams. HEADERS/DATA carry request/response fields/content; stream lifecycle and flow control bound concurrent work. Pseudo-headers such as :method, :scheme, :authority, and :path are required/ordered before regular fields; regular field names are lowercase on the wire. This is protocol validation, not a client fingerprint.

04 · SETTINGS and multiplexing

SETTINGS communicates connection parameters; it is not an application authentication mechanism. Stream IDs/order and frame timing can provide operational telemetry at a trusted terminating endpoint, but intermediaries, libraries, versions, and connection reuse alter them. Respect configured resource limits rather than treating protocol concurrency as unlimited.

05 · HPACK

HTTP/2 HPACK compresses header fields using static/dynamic tables and indexed/literal representations. It reduces repeated header bytes but makes raw passive header interpretation nontrivial and creates decoder resource considerations. Use maintained implementations with configured limits; do not implement a general decoder from this guide.

06 · Head-of-line blocking

HTTP/2 multiplexing avoids HTTP/1.1 application-level request serialization within a connection, but HTTP/2 rides one TCP byte stream: lost TCP data can delay later stream bytes at transport level. This is distinct from application stream concurrency and explains why HTTP/3/QUIC changes loss isolation.

07 · HTTP/3 / QUIC

RFC 9114 maps HTTP semantics onto QUIC over UDP, with independent QUIC streams and QPACK header compression. QUIC encrypts much transport metadata and supports connection migration; passive observers commonly see UDP flow/packet timing/size and possibly handshake-visible information depending on encryption/version/path, not HTTP headers/routes. Exact visibility depends on TLS/QUIC version, endpoint, and where observation occurs.

09 · Safety

Version is not a bot verdictHTTP/2 SETTINGS, stream behavior, header encoding, and HTTP/3 use vary legitimately by browser, CDN, network, and library. Use only authorized local/client-controlled observations and combine signals with robust false-positive analysis.

10 · Detection scenarios

LOAD

One TCP connection has many requests

Instrument request/stream counts at the trusted terminator; do not infer per-request rate from connection count.

LATENCY

HTTP/2 streams stall together

Distinguish TCP-loss transport HOL from application handler latency using endpoint metrics.

VISIBILITY

HTTP/3 shifts network telemetry

Update passive sensor expectations for QUIC/UDP; rely on edge/origin logs for route semantics.

LIMITS

Many streams pressure service

Use server/CDN configured stream/body/time limits and monitor rejections, without interpreting every limit hit as hostile.
