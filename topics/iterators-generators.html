01 · Purpose

Why this matters in detection engineering

Log ingestion, PCAP parsing, API pagination, and event enrichment are all sequences. Treating every sequence as a list hides cost and lifetime; treating it as an iterator makes backpressure, exhaustion, and failure boundaries observable.

MEMORY

Streaming is bounded

A consumer asks for one event. A pipeline can run on a large file without keeping all prior events.

EVIDENCE

Order has meaning

Iterators preserve encounter order, useful for a timeline, first-seen logic, and deterministic triage.

RELIABILITY

End is a signal

Normal exhaustion differs from a parser exception, network timeout, or malformed record.

INTERVIEWS

Mechanism beats folklore

You can explain exactly how for obtains values instead of merely saying generators are “faster.”

02 · Mental model

A consumer pulls; the iterator remembers where it is

An iterable can produce an iterator. The iterator supplies the next value or raises StopIteration. It is normally single-pass: once its internal cursor reaches the end, asking again does not rewind it.

IterableA collection or source that can make an iterator.iter(source)
→
IteratorStateful cursor: returns one value at a time.next(cursor)
→
ConsumerProcesses, stores, or discards each value.for event in …

A list is reusable because each iter(list) creates a fresh cursor. A generator object is itself its cursor, so a completed generator stays completed.

records = ["ok", "bad"]
cursor = iter(records)
print(next(cursor))  # ok
print(next(cursor))  # bad
# next(cursor) now raises StopIteration: normal end of this cursor.

03 · Protocol

What a for loop actually does

This is conceptual desugaring, not code to copy into production. The loop calls iter() once, then calls next() until normal exhaustion. It does not collect values first.

cursor = iter(source)
while True:
    try:
        item = next(cursor)
    except StopIteration:
        break
    handle(item)
iter(source)

Obtain a fresh iterator where the source supports it.Use it to make cursor creation explicit. It assumes source implements __iter__ or the sequence fallback; calling it on an exhausted generator returns that same exhausted object.

next(cursor, default)

Pull one value, optionally with a sentinel default.Use the default only when end-of-stream is expected and distinguishable from real data. A value such as None is unsafe as a default if valid records can be None.

list(iterator)

Materialize every remaining value.Use only for known-small, bounded data or a deliberate snapshot. It consumes a single-pass iterator and can expose sensitive records or exhaust memory on production-scale input.

class NumberedLines:
    def __init__(self, lines):
        self._lines = lines
        self._index = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self._index == len(self._lines):
            raise StopIteration
        value = (self._index + 1, self._lines[self._index])
        self._index += 1
        return value

This iterator class owns mutable cursor state. Its __next__ must either return a value or raise StopIteration; returning a special “end” value would make that value look like a real record.

04 · Lazy producer

yield saves the frame, then resumes it

Calling a generator function returns a generator object without running its body. Each next() runs until the next yield, preserving local variables and instruction position. Generator expressions use the same lazy idea.

def parsed_events(lines):
    for line_number, raw in enumerate(lines, start=1):
        text = raw.rstrip("\n")
        if not text:
            continue
        if "|" not in text:
            raise ValueError(f"line {line_number}: expected ts|ip|status")
        timestamp, ip, status = text.split("|", 2)
        yield {"line": line_number, "ts": timestamp, "ip": ip, "status": int(status)}

high_risk = (event for event in parsed_events(lines) if event["status"] >= 500)

Do not use return value to emit a final record from a generator: it ends the generator and its value is carried in StopIteration.value, which ordinary for ignores. Raise a contextual exception for malformed input; do not convert it to StopIteration inside a generator, because Python transforms that mistake into RuntimeError (PEP 479 behavior in modern Python).

05 · I/O boundary

Keep the resource open for the entire pull sequence

A file object is iterable by lines, but it is also a resource. The safest shape opens it inside the generator’s execution and lets with close it whether processing completes or raises.

from pathlib import Path

def stream_log(path: Path):
    # utf-8 is an input contract; replace only with the known producer encoding.
    with path.open("r", encoding="utf-8", errors="strict") as handle:
        for line_number, line in enumerate(handle, 1):
            yield line_number, line.rstrip("\n")

for line_number, line in stream_log(Path("artifacts/events.log")):
    print(line_number, line)
Lifetime trapDo not return a generator expression over a file opened in a finished with block: the consumer will later read a closed handle. If a caller stops early, call generator.close() when prompt cleanup matters, or consume it within a surrounding context manager.

Assumptions and platform detail: the examples target CPython 3.11+ but use standard Python semantics. File buffering, descriptor limits, and when garbage collection runs differ by implementation and OS; never rely on object destruction to close a file. On Windows, an open file is often harder to rename or remove than on POSIX, making explicit closure especially visible.

06 · Failure modes & safety

Separate normal exhaustion from evidence loss

FailureWhy it happensDefensive response
Second pass is emptyA generator or file cursor was already consumed.Create a fresh iterator from a replayable source, or deliberately persist a sanitized bounded snapshot.
list(stream) stalls or crashesFull materialization removed the memory bound.Aggregate incrementally; enforce input limits and record counts.
Malformed record disappearsA broad except silently skips it.Count and quarantine failures with line number; choose a documented fail-open/fail-closed policy.
Closed-file errorProducer outlives its file context.Own the file context inside the streaming generator or consume before exit.
Generator error is hiddenCalling code catches too broadly or never iterates.Test the first pull and a malformed case; catch only expected exceptions.

07 · On the job

Detection-engineering scenarios

INGEST

Overnight proxy export is larger than RAM

Stream lines, parse one event, and update counters. Keep a count of parse rejects. The resulting top sources are a lead, not proof of an actor—proxy and NAT identity boundaries still apply.

PIPELINE

An enrichment stream appears to have no events

Check whether a debug statement called list(events) before the real consumer. Rebuild the stream from the original source and make diagnostics count rather than consume the source.

TRIAGE

First five malformed events need review

Use itertools.islice on an explicitly constructed stream to cap a sample, save redacted line numbers and reasons, then continue only if policy permits. Do not dump every raw record into a ticket.

RELIABILITY

Consumer stops at a high-severity alert

Ensure the generator owns its file context and closes promptly. Record the stop reason and offset so the investigation can replay from a known artifact instead of assuming all input was processed.

08 · Practice

Hands-on drills

1. Build both forms from blank

30 min

In a new artifacts/iterators/ directory, save iterator.py with an iterator class and generator.py with an equivalent generator for three synthetic records. Save transcript.txt showing values then normal exhaustion.

  • Point to where each implementation stores its cursor.
  • Explain what for calls and why StopIteration is not printed as a record.
  • Demonstrate that a completed generator cannot be rewound.

2. Stream a mock access log

35 min

Create events.log with at least 20 lines and one intentionally malformed line. Save stream_summary.json with total, 5xx count, and reject count; do not call read() or readlines().

  • Show the input encoding and malformed-line policy.
  • Show that one record is handled at a time.
  • Explain why the saved summary is safer to share than raw logs.

3. Prove cleanup and early stop

20 min

Write a generator that logs “opened” and “closed” around its with block. Consume two records, close it explicitly, and save lifetime-transcript.txt.

  • Identify the point at which the file becomes open and closed.
  • Describe why garbage collection is not a resource-management policy.
  • State how you would resume from a saved file offset in a real pipeline.
