Map risk categories to implemented controls.

OWASP lists are versioned awareness frameworks, not a compliance checkbox. Record the Web/API Top 10 edition used and map each applicable category to AbuseGuard control, test, evidence, and gap.

Why it matters

Category names help organize review, but each finding needs an actual entry point, asset, control, and test. Record source edition/date because OWASP categories change.

Record current source version

As checked against the official projects in August 2026, the current released editions are OWASP Top 10:2025 and OWASP API Security Top 10:2023. Write both edition names and your retrieval/review date in the matrix. Recheck the primary project pages when doing the drill; do not silently mix categories from older editions.

Web Top 10 mapping

The 2025 Web list is: Broken Access Control; Security Misconfiguration; Software Supply Chain Failures; Cryptographic Failures; Injection; Insecure Design; Authentication Failures; Software or Data Integrity Failures; Security Logging and Alerting Failures; and Mishandling of Exceptional Conditions. Use these exact edition-qualified names, then map each to actual AbuseGuard routes/components. Do not paste a 2021 list and label it 2025.

API Top 10 mapping

The 2023 API list separates broken object-, property-, and function-level authorization; unrestricted resource consumption; unrestricted access to sensitive business flows; SSRF; security misconfiguration; improper inventory management; and unsafe consumption of APIs, alongside broken authentication. This API lens helps distinguish “may access this report?” from “may change this report field?” and “may call this admin function?”

BOLA is object authorization

Every object ID must be scoped to authenticated principal and tenant server-side. Opaque IDs and UI hiding are not controls. Test read/update/delete/export with two synthetic tenants.

Mass assignment/property authorization

Accept declared request models, ignore/reject privileged fields, and map input to allowed domain fields explicitly. Validation is not enough if an allowed-looking field changes role, tenant, price, or policy.

Evidence is more than a code claim

Attach test name, configuration path, review date, owner, and residual risk. A passing unit test does not prove production headers, proxy trust, dependency posture, or operational monitoring.

Safety and limits

Review local synthetic AbuseGuard only; do not test public targets. The lists are not exhaustive and no control is universal. Apply threat-model context and accepted-risk review.
