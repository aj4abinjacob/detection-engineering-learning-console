Parse the handshake before you summarize it.

01 · Purpose

A ClientHello is a structured offer

TLS negotiation begins with a client’s offered version/cipher/extensions and related parameters. Parse it completely and boundedly before comparing order or computing a fingerprint.

COMPATIBILITY

Offer, not identity

Server chooses from compatible values.

ORDER

Implementation clue

Order can be stable per client build/config.

GREASE

Extensibility signal

Reserved values exercise tolerant implementations.

POINT

Where observed

Proxy/TLS termination can replace it.

02 · TLS ClientHello structure

Handshake { type=client_hello, length }
ClientHello { legacy_version, random, legacy_session_id,
  cipher_suites, legacy_compression_methods, extensions }
extensions = [type, length, extension_data] in transmitted order

RFC 8446 defines TLS 1.3 compatibility fields and extensions such as supported_versions, server_name, supported_groups, signature_algorithms, ALPN, and key_share. TLS records can fragment handshake bytes; a correct parser reassembles bounded handshake data before interpreting length-prefixed vectors. Do not equate legacy_version with negotiated TLS version.

03 · Every vector is length-prefixed

Read the outer handshake length, then each vector length, and reject truncation, impossible nesting, duplicate forbidden/unsupported fields per your policy, and configured size/count excess. Capture metadata should preserve byte offsets and parser outcome. A field list without its surrounding lengths is not a full ClientHello parser.

04 · Extensions and order

Extension type is 16-bit; data semantics depend on type. Preserve transmitted order and repeated values where protocol/library policy permits; do not sort before analysis. Some extensions contain their own ordered lists (cipher suites, groups, signature algorithms, ALPN protocols). Define exactly which level your artifact records.

05 · GREASE

GREASE (RFC 8701) uses reserved values such as 0x0a0a through 0xfafa in selected extension points to keep ecosystems tolerant of unknown values. A parser should recognize/report or normalize GREASE only according to the fingerprint method’s specification, while retaining raw capture evidence separately. GREASE presence/placement is not proof of browser, automation, safety, or maliciousness.

06 · Stability needs measurement

Compare same client/version/config across several learner-owned captures, then compare clients at the same observation point. Order can change with TLS library, OS updates, feature flags, proxying, retry/version fallback, GREASE rotation, and capture/parser behavior. Describe a measured stability rate and sample conditions; never write “this order identifies Chrome.”

07 · Synthetic bounded parser

def take(blob: bytes, offset: int, size: int) -> tuple[bytes, int]:
    if size < 0 or offset + size > len(blob): raise ValueError("truncated")
    return blob[offset:offset + size], offset + size
# Apply declared MAX_HANDSHAKE/MAX_EXTENSIONS before any allocation.
# Lab fixture only: not a socket/TLS implementation.

Use: unit-test offset/length validation on synthetic fixtures. Risk: this is not a TLS stack; no live listener, shared-interface capture, or third-party connection is needed.

08 · Observation point

A direct server can observe the peer’s ClientHello if it terminates TLS. A reverse proxy/CDN terminator sees client→edge TLS; an origin commonly sees proxy→origin TLS instead. Passive capture visibility depends on legal authorization and encryption path. Record capture ownership, timestamp, endpoint roles, parser version, and whether data was sanitized.

09 · Safety

Fingerprint evidence is not identity or intentUse sanitized existing learner-owned captures or synthetic fixtures only. Do not connect to third parties, capture shared interfaces, or use ordering knowledge to evade a control.

10 · Defensive scenarios

CHANGE

Client extension order shifts after update

Trigger: observed order change. Artifact: owned capture diff. Observation: new library/version. Reasoning: implementation change plausible. Boundary: no identity/fraud label.

GREASE

Unknown-looking values appear

Trigger: reserved pattern. Artifact: parser field offsets. Observation: GREASE. Reasoning: extensibility mechanism. Boundary: do not reject as malformed by default.

PROXY

Origin sees uniform Hello

Trigger: one pattern across users. Artifact: topology diagram. Observation: TLS terminator peer. Reasoning: proxy→origin handshake. Boundary: cannot infer end client.

PARSER

Truncated fixture rejected

Trigger: length mismatch. Artifact: unit test. Observation: safe rejection. Reasoning: parser limit works. Boundary: no live malformed traffic.
