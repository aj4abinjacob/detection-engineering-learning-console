Why it matters

Security bugs hide in a path, not only a line. A source-to-sink trace identifies where untrusted values become a query, HTML, file, redirect, command, log, or authorization decision.

Identify sources

Sources include path/query/body/form/header/cookie/file/env/config/database records from less trusted systems. Record trust level and whether upstream validation can be bypassed.

Follow transformations

Trace parsing, normalization, defaulting, serialization, ORM mapping, template context, and logging. A value can become dangerous after decoding or concatenation, even when initial validation looked safe.

Validate by contract

Use typed allowlists/ranges/schema at boundary; reject unexpected data. Validation is context-specific: a valid display string is not automatically a SQL identifier or HTML-safe value.

Authorize objects

Before sensitive sink/action, derive tenant/principal from server-authenticated state and check object/action policy. Never use client-supplied tenant/role as authority.

Classify sinks

SQL requires parameters; HTML/template requires context-aware escaping; URL redirect requires destination allowlist; filesystem requires fixed base/validated path; logs require redaction and newline-safe structure. Avoid shell command sinks entirely where possible.

Encode at final context

Output encoding belongs at the final sink/context, not blanket early escaping. Avoid double decoding/encoding and do not confuse sanitization for one context with authorization.

Convert threats to tests

For each threat, write a minimal synthetic test: cross-tenant object denied, parameter value stays data, privileged field rejected, unsafe redirect rejected, secret absent from log. Assert behavior and safe error output.

Review worksheet

source; trust; transformations; validation; authz; sink/context; encoding; test; residual risk

Keep scope bounded to one route/path. Record code version and review date; use local synthetic payload shapes, not real attack traffic.

Worked trace: report search

  1. Source: authenticated GET /reports?q=failed; query text is untrusted, principal comes from a verified server session.
  2. Parse/normalize: decode once under framework rules, require a string, bound it to 100 characters; do not mutate it into SQL syntax.
  3. Authorize: derive tenant_id from the principal, never a query parameter.
  4. SQL sink: repository binds both values as parameters and scopes by tenant; the query value remains data.
  5. HTML sink: template applies context-aware escaping to the echoed search label; do not reuse SQL quoting.
  6. Log sink: emit route template, length bucket, outcome, and pseudonymous tenant—not the raw search value.

Tests should prove cross-tenant denial, quote/metacharacter treatment as data, bounded input, HTML escaping in rendered output, and absence of the raw value from broad logs.
