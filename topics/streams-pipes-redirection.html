01 · Purpose

Why streams matter in detection work

01 · TRIAGE

Answer questions in seconds

Filter a log, select a field, count values, and rank the result without pausing to build a full parser.

02 · COMPOSITION

Each tool does one transformation

A pipeline exposes each step, making it easy to inspect intermediate data and replace weak assumptions.

03 · AUTOMATION

Separate result from diagnostics

stdout can feed the next stage while stderr remains visible or goes to a dedicated operational log.

04 · SCALE

Process incrementally

Many filters stream line by line rather than loading an entire capture into memory.

The useful definitionA stream is an ordered sequence of bytes. Programs commonly start with three open file descriptors: stdin 0, stdout 1, and stderr 2. The shell can connect each descriptor to a terminal, file, pipe, or device.

02 · Start here

Read the data before you start routing it

The simplest commands answer one question at a time: “show me this short file,” “show me the first ten lines,” or “let me move through a long file.” Learn those first; pipes and redirection then feel like connecting familiar pieces.

cat short.txt

Write the whole file to stdout.Good for a small file; noisy and awkward for a very large one.

less long.log

Open a scrollable view.Use arrow/Page keys, /text to search, n for the next match, and q to quit in the usual less configuration.

head -n 20 app.log

Show the beginning.Useful for headers, schemas, and a quick format check.

tail -n 20 app.log

Show the end.tail -f keeps watching appended data; stop it with the terminal's interrupt key, normally Ctrl-C.

Make a tiny file, then observe each route

printf 'allow\ndeny\nallow\n' > decisions.txt
cat decisions.txt
head -n 1 decisions.txt
tail -n 1 decisions.txt
wc -l < decisions.txt
sort decisions.txt | uniq -c
  1. printf produces stdout.It is more predictable than echo in scripts when text contains backslashes or begins with option-like characters.
  2. > is handled by the shell.The shell opens or truncates decisions.txt before starting printf, then connects the command's stdout to that file.
  3. < changes stdin.wc reads bytes from the file without receiving a filename argument, so its output contains only the count.
  4. | connects two processes.sort writes ordered lines; uniq -c reads them and counts adjacent equal lines.
Redirection is not an editor> replaces an existing destination's content; >> appends. The redirection happens before the command runs, so sort file > file can empty the input before sort reads it. Write to a different file, inspect it, then replace deliberately.

Verified against: the GNU Bash manual sections on redirections and pipelines and shell operation, plus the GNU Coreutils manual for cat, head, tail, wc, sort, and uniq.

03 · Command walkthroughs

Count, search, edit, and reshape text

These tools do not all understand the same language. find -name uses shell-style pathname patterns, grep/sed/awk use regular expressions, and cut knows only positions or a simple delimiter. Start by naming the input format and the parser you are asking to read it.

wc, sort, and uniq

wc notes.txt             # lines, words, bytes, then filename
wc -l notes.txt          # newline count
wc -w notes.txt          # words according to wc's rules
wc -c notes.txt          # bytes; -m requests characters
wc -l < notes.txt        # same data, but no filename operand to print

LC_ALL=C sort values.txt
sort -n scores.txt       # numeric rather than lexicographic order
sort -k2,2 users.txt     # use field 2 as the key
sort values.txt | uniq -c | sort -nr
CommandThe detail that prevents mistakes
wc -lCounts newline characters. A final unterminated record can make “lines” and logical records differ.
sortWrites sorted output; it does not rewrite the input file. Locale affects collation, so record LC_ALL when exact grouping must be reproducible.
sort -nCompares numeric values. Plain sort is lexical, so text 10 can appear before 2.
uniqOnly compares adjacent lines. Sort or otherwise group equal values first when the duplicates are scattered.
uniq -cPrefixes each adjacent group with its count. -d shows duplicate groups; it does not tell you about non-adjacent duplicates by itself.

grep: select lines; sed: edit a stream

grep reads a pattern, then input

grep -nF 'literal.value' app.log     # fixed string, with line numbers
grep -nE '^(allow|deny) ' app.log    # extended regular expression
grep -i 'failed login' app.log       # ignore case distinctions
grep -v '^#' config.txt              # invert: lines that do not match
grep -c 'ERROR' app.log              # count matching lines, not occurrences
grep -l 'secret' -- *.conf           # print names of matching files
grep -r -nF 'api_key' configs/       # recursively search file contents
Regular-expression formMeaningDo not confuse it with
^start / end$Anchor at the start/end of a line.A shell prompt or shell variable expansion.
.Any one character.A literal dot; write \. for that.
[abc] / [^abc]One listed character / one character not listed.A whole word choice.
x*Zero or more of the preceding atom x.The shell glob *, which stands alone for pathname characters.
x+, x?, a|bOne-or-more, optional, or alternation with grep -E.Shell pipe syntax; quote the whole pattern.

grep normally exits 0 when it selected a line, 1 when it selected none, and 2 on an error. “No match” is therefore a useful documented outcome, not automatically a broken command.

sed has addresses and commands

# s/pattern/replacement/ changes the first match on each selected line.
sed 's/denied/blocked/' events.txt

# g changes every non-overlapping match on each selected line.
sed 's/denied/blocked/g' events.txt

# A different delimiter is easier when the values contain slashes.
sed 's#/old/path#/new/path#g' paths.txt

# -n disables automatic printing; p explicitly prints selected lines.
sed -n '1p' events.txt
sed -n '5,9p' events.txt
sed -n '/ERROR/p' events.txt
sed -n '2,$p' events.txt

# Multiple scripts can be written separately or loaded from a file.
sed -e 's/foo/bar/g' -e '/^#/d' input.txt
sed -f cleanup.sed input.txt
  1. Input remains unchanged by default.sed writes the transformed stream to stdout; redirect it to a different file if you want to save it.
  2. The first delimiter defines the rest./ is conventional, not required. Pick a delimiter that makes the script readable.
  3. An address narrows a command.A line number, range, or /regexp/ before s, p, or d chooses which records receive that command.
  4. -E enables extended regular expressions.This reduces escaping for groups and alternation, but replacement backreferences still use forms such as \1.
Delay in-place editingsed -i syntax and backup behavior differ between GNU and BSD/macOS implementations. While learning—or when editing evidence—write to a new file, compare it, and replace only after validation.

tr, cut, awk, and xargs

tr transforms character sets from stdin

tr '[:lower:]' '[:upper:]' < names.txt
tr -d '\r' < windows-lines.txt > unix-lines.txt
tr -s '[:space:]' ' ' < irregular.txt

tr SET1 SET2 maps characters; it does not accept a filename operand in the usual interface. -d deletes characters from a set and -s squeezes repeated characters from the selected set. Character classes and locale affect what counts as lower case or whitespace.

cut selects positions or simple delimiter fields

cut -c 1-12 fixed-width.txt
cut -d: -f1,7 /etc/passwd
cut -f2-4 tab-separated.tsv

-c selects character positions, -d sets one field delimiter, and -f selects fields. cut -d, is not a CSV parser: quoting, embedded commas, and embedded newlines require a CSV-aware tool.

awk is a pattern–action language

# Default records are lines and default fields are whitespace-separated.
awk '{ print $1, $NF }' access.log

# Choose a delimiter and select a condition.
awk -F '\t' '$3 == "blocked" { print NR, $1, $3 }' events.tsv

# BEGIN runs before input; END runs after all records.
awk '
  BEGIN { errors = 0 }
  $9 ~ /^5[0-9][0-9]$/ { errors++ }
  END { printf "5xx=%d records=%d\n", errors, NR }
' access.log
NameMeaning
$0The whole current record.
$1 … $NFThe first through last current fields.
NFNumber of fields in the current record.
NR / FNRTotal record number / record number within the current file.
FS / OFSInput and output field separators.

Putting an awk program in single quotes protects $1 and other syntax from the shell. If shell data must enter the program, pass it as an awk variable with -v name="$shell_value" instead of splicing text into program source.

xargs turns an input stream into argument lists

printf '%s\n' one two three | xargs -n 2 printf '<%s>\n'

# Safe for arbitrary pathnames because the boundary is NUL, not whitespace.
find logs -type f -name '*.json' -print0 \
  | xargs -0 sha256sum --

With no command, GNU xargs uses echo. -n 2 supplies at most two input arguments per invocation; -I {} substitutes one logical input item into a template but changes batching behavior. Default whitespace parsing cannot preserve arbitrary pathnames. Prefer find ... -exec command {} + when it expresses the job directly, or pair -print0 with xargs -0.

Structured data deserves a structured parserThe video examples use friendly teaching files. Production logs may contain quoted delimiters, Unicode, multiline records, binary data, or attacker-controlled filenames. Confirm the input contract before choosing a text tool.

Verified against: the GNU manuals for Coreutils, grep, sed, awk, and xargs.

04 · Mental model

Programs read and write file descriptors

InputBytes arrive through stdin or a file explicitly opened by the program.0 < access.log
→
TransformA process parses, filters, maps, counts, or formats the byte stream.awk '{print $1}'
→
OutputResult bytes leave on stdout; diagnostics should leave on stderr.1 > report.txt

A pipe connects the stdout descriptor of one process to the stdin descriptor of another. The shell creates both processes and the kernel transports the bytes.

DescriptorNameIntended roleDefault
0stdinData consumed by the programTerminal keyboard/session input
1stdoutSuccessful result dataTerminal display
2stderrDiagnostics and errorsTerminal display
 
python3 -c 'import sys
print("result", file=sys.stdout)
print("diagnostic", file=sys.stderr)' \
  > result.txt 2> diagnostic.txt
Lines are a convention, not the transportPipes carry bytes and apply back-pressure. Line-oriented tools may buffer when stdout is no longer a terminal, and binary or multi-line records can break “one line equals one event” assumptions.

05 · Routing

Redirection is evaluated left to right

SyntaxMeaningCaution
cmd < inputOpen file as stdinThe command may also accept a filename argument; these are different interfaces.
cmd > outputOpen/truncate file as stdoutExisting content is replaced before the command runs.
cmd >> outputOpen file for append as stdoutConcurrent writers may interleave multi-write records.
cmd 2> errorsSend stderr to a fileDo not hide diagnostics before confirming expected behavior.
cmd 2>&1Duplicate current stdout onto stderrOrder matters because it copies the current destination.
cmd > all 2>&1Send both streams to one fileCorrect order for one combined file.
cmd > /dev/nullDiscard stdoutUse sparingly; missing output can hide an operational clue.

Why order changes behavior

# Both stdout and stderr go to combined.log
command > combined.log 2>&1

# stderr keeps the terminal destination; only stdout goes to output.log
command 2>&1 > output.log

In the second form, stderr first duplicates stdout's current terminal destination. stdout is redirected afterward, but stderr remains connected to the terminal.

tee: save and continue

# Display output and write the same bytes to a file
command | tee output.log

# Include stderr in the stream first
command 2>&1 | tee combined.log
Do not overwrite source evidenceNever redirect a command's output to the same file it is reading with >; the shell truncates the destination before the program reads it. Write to a new file, validate it, then perform an explicit replacement if intended.

06 · Composition

Build pipelines one verified stage at a time

# Question: which IPs appear most often in a simple access log?
awk '{print $1}' access.log \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -10
  1. State the input contract. This example assumes the first whitespace-delimited field is an IP and each request is one line.
  2. Verify extraction. Run only awk '{print $1}' and sample its output.
  3. Group identical values. uniq -c counts adjacent equal lines, so sort must group them first.
  4. Rank numerically. sort -nr sorts counts as numbers, descending.
  5. Limit presentation. head -10 changes display, not the upstream calculation.

Pipeline status

Without pipefail, a shell normally reports the final command's status. An early parser can fail while head exits successfully.

set -o pipefail
generate_events | parse_events | write_summary
status=$?
printf 'pipeline status=%s\n' "$status"
SIGPIPE can be normalA limiting command such as head exits after receiving enough data. An upstream writer may then receive a broken-pipe signal. Under strict pipefail, understand whether that status reflects expected early termination or a real failure.

07 · Text toolkit

Know each filter's contract

grep -nE '5[0-9]{2}' file

Select matching lines.-n preserves line numbers; -E selects extended regular expressions. Use -F for literal strings.

cut -d, -f1,4 file.csv

Select delimited fields.Only safe for simple delimiters; quoted CSV with embedded commas needs a CSV parser.

sort

Order lines.Use -n for numeric, -r for reverse, -k for fields, and consider LC_ALL=C for stable byte-order behavior.

uniq -c

Count adjacent identical lines.Usually pair with sort; it does not count equal lines scattered through input.

awk '{count[$1]++} END {...}'

Field-aware transform and aggregate.Powerful for whitespace/delimited text; document field assumptions.

sed -n '20,40p' file

Select or transform text ranges.Prefer non-destructive output while exploring; in-place flags differ across platforms.

wc -l

Count newline characters.A file lacking a final newline may contain more logical data than the line count suggests.

head -n 20 / tail -n 20

Sample boundaries.tail -f follows growth; rotation behavior depends on implementation and flags.

Locale and reproducibility

# Stable byte-wise sort/group behavior for an artifact
LC_ALL=C awk '{print $1}' access.log \
  | LC_ALL=C sort \
  | uniq -c \
  | sort -nr

Locale can affect collation, character classes, case conversion, and numeric formatting. Record it when exact output must be reproduced.

08 · Honest parsing

Use structure-aware tools for structured data

InputPreferAvoid assuming
Whitespace access logawk after verifying formatUser-agent or quoted fields never contain spaces.
JSON LinesjqFields appear in a fixed textual order.
CSVPython csv, Miller, or another CSV parsercut -d, handles quoted commas/newlines.
NUL-delimited pathsfind -print0 plus compatible consumerFilenames cannot contain whitespace or newlines.
Binary capturetcpdump, tshark, format libraryText filters preserve binary record boundaries.
 
# Count JSONL events by source IP, ignoring null/missing values
jq -r 'select(.source_ip != null) | .source_ip' events.jsonl \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -10
Fast does not mean carelessShell pipelines are excellent for exploration and operational glue. Promote the logic to a tested parser when input structure is complex, correctness is security-sensitive, or the transformation becomes a production dependency.

09 · On the job

Detection-engineering scenarios

TOP TALKERS

Find top source IPs in an access log

LC_ALL=C awk '{print $1}' access.log \
  | sort | uniq -c | sort -nr | head -10

Validate first: sample records, confirm field 1 is the client identity, and account for trusted-proxy headers before treating it as a source IP.

ERROR RATE

Calculate 5xx percentage for a known log format

awk '
  { total++; if ($9 ~ /^5[0-9][0-9]$/) errors++ }
  END {
    if (total == 0) { print "no records" > "/dev/stderr"; exit 2 }
    printf "5xx=%d total=%d rate=%.2f%%\n",
           errors, total, 100 * errors / total
  }' access.log

Why awk: one pass avoids separate counts drifting across different filters. The field assumption remains the critical part to document.

DUAL OUTPUT

Save machine-readable findings while preserving errors

python3 analyzer.py access.log \
  > findings.json \
  2> analyzer-errors.log
status=$?
printf 'status=%s\n' "$status"

Why it matters: downstream tools receive clean JSON, while humans retain warnings and stack traces separately.

LIVE WATCH

Watch matching events without modifying the log

tail -F application.log \
  | grep --line-buffered -E 'login_failed|credential_stuffing'

Caution: -F and --line-buffered are not uniformly portable. Live tails are observation aids, not durable ingestion; rotation and disconnects can lose events.

SAFE PATHS

Hash every capture even when filenames contain spaces

find captures -type f -print0 \
  | xargs -0 shasum -a 256

Why NUL delimiters: newline-delimited filename pipelines cannot represent every valid Unix pathname safely.

10 · Practice

Hands-on drills

1. Top ten IPs using only pipes

20 min

Using your Week 0 access-log fixture, compute top ten IPs without Python. Inspect the output after every pipeline stage.

  • Write the input format assumption above the command.
  • Explain why sort comes before uniq -c.
  • Compare the result with your Python analyzer and explain any mismatch.

2. Route all three streams

15 min
python3 -c 'import sys
print("input=" + sys.stdin.read().strip())
print("warning", file=sys.stderr)' \
  < input.txt \
  > result.txt \
  2> errors.txt
printf 'status=%s\n' "$?"
  • Predict each file's content before running.
  • Repeat with combined stdout/stderr and explain redirection order.
  • Replace > with >> and explain repeat-run behavior.

3. Make failures observable

20 min

Create a three-stage pipeline whose first command fails. Compare its exit status with and without set -o pipefail, then capture the relevant status in a script.

  • Explain why the default pipeline status can lie.
  • Observe what changes when the final consumer is head.
  • Document stdout, stderr, and exit-status contracts for your analyzer.
