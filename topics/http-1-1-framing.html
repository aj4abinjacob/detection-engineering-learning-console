Practical field guide · HTTP/1.1

Know where one message ends.

HTTP/1.1 connections can carry multiple messages. Framing rules prevent one component from treating bytes as a different request than another.

01 · Purpose

A persistent connection is a byte stream. Sender and recipient must agree on request/response boundaries before method, route, and body telemetry means anything.

02 · HTTP/1.1 byte model

start-line\r\n
field-name: value\r\n
\r\n
message content bytes...

HTTP/1.1 uses CRLF-delimited start/header lines and specified message-body length. Connection reuse/keep-alive means the next message may follow immediately after current content. RFC 9112 defines the recipient algorithm; implementers should use mature servers/proxies, not a learning parser for Internet traffic.

03 · Content-Length

Content-Length declares decimal content length when applicable. Reject invalid values, conflicting repeated values, unsupported overflow, and content beyond a configured cap. A recipient must not “read until socket close” when a length/transfer coding rules the message; connection closure is not a general safe delimiter for all messages.

04 · Transfer-Encoding: chunked

4\r\nWiki\r\n
5\r\npedia\r\n
0\r\n\r\n

Chunked coding sends hex chunk size, chunk bytes, CRLF, then zero-size terminator/trailer section. It is HTTP/1.1 transfer coding, not application JSON framing. A bounded parser must validate hex, CRLF, total decoded bytes, chunk count, trailer policy, and EOF/timeouts.

05 · Framing precedence and rejection

RFC 9112 specifies message-body length precedence. Transfer-Encoding overrides Content-Length for framing; messages containing both require defensive handling because ambiguity across components is dangerous. Servers/proxies should reject invalid/malformed/ambiguous framing rather than guess or normalize it into a different request. Exact recipient obligations depend on role and version; consult RFC 9112 for implementation work.

06 · Bounded local parser exercise

def read_exact(data: bytes, length: int, max_body=1_048_576) -> bytes:
    if not 0 <= length <= max_body: raise ValueError("body limit")
    if len(data) != length: raise ValueError("truncated/extra lab body")
    return data

def decode_chunked(data: bytes, max_body=1_048_576, max_chunks=1024) -> bytes:
    body, pos, chunks = bytearray(), 0, 0
    while True:
        line_end = data.find(b"\r\n", pos)
        if line_end < 0 or line_end - pos > 16:
            raise ValueError("missing/oversized chunk-size line")
        size_text = data[pos:line_end].split(b";", 1)[0]
        if not size_text or any(c not in b"0123456789abcdefABCDEF" for c in size_text):
            raise ValueError("invalid chunk size")
        size, pos = int(size_text, 16), line_end + 2
        if size == 0:
            if data[pos:] != b"\r\n":
                raise ValueError("trailers/extra bytes unsupported in this lab")
            return bytes(body)
        chunks += 1
        if chunks > max_chunks or size > max_body - len(body):
            raise ValueError("chunk/body limit")
        end = pos + size
        if end + 2 > len(data) or data[end:end + 2] != b"\r\n":
            raise ValueError("truncated chunk or missing CRLF")
        body.extend(data[pos:end])
        pos = end + 2
# Lab primitive only: no production HTTP parser claim.

Use: unit-test fixed-length and final-chunked framing invariants against synthetic byte strings, including b"0\r\n\r\n" for an empty chunked body. This intentionally rejects trailers/extensions beyond ignoring an extension on the size line; extending policy requires new tests. Risk: these are learning primitives, not a complete recipient: start-line/header parsing, field combination, role/status semantics, network timeouts, and every RFC rule remain outside them. Never expose this parser as an Internet service.

07 · Keep-alive and intermediaries

HTTP/1.1 persistent connections save handshakes but make framing correctness essential. Connection-specific fields and hop-by-hop behavior differ from end-to-end fields; a proxy may parse, strip, add, or reserialize. Capture which component generated telemetry before comparing header/body facts across hops.

08 · Defensive request-smuggling concept

Request smuggling is a class of desynchronization where front-end and back-end components disagree about boundaries. Treat it as a configuration/parser consistency problem: patch supported servers, use one well-tested edge parser, reject ambiguous framing, and test only authorized local staging with benign fixtures. This guide intentionally provides no exploit payloads or third-party testing instructions.

09 · Safety

Never parse unbounded streams in a lab scriptSet header/body/chunk/time limits and reject malformed input. Static synthetic bytes cover malformed cases; the raw-client drill may connect only to the learner-owned loopback fixture and must not send malformed framing to any third-party or production system.

10 · Detection scenarios

EDGE

Proxy logs body-size mismatch

Correlate component, parsed framing decision, status, and connection outcome; do not reconstruct body content into logs.

OUTAGE

Clients hang on reused connections

Inspect server/proxy versions and bounded rejection metrics; a framing bug can poison subsequent connection messages.

ABUSE

Malformed request spike

Count rejection categories and source provenance, rate-limit at edge, and retain sanitized samples under policy.

DEPLOY

Two hops parse differently

Compare supported configuration/version behavior in an authorized staging environment; remediate consistency rather than probing live targets.

11 · Practice

Hands-on drills

1. Build the bounded loopback raw client

45 min

Against a learner-owned loopback HTTP/1.1 fixture, build a one-response raw client with connect/read timeouts, a 16 KiB header cap, the body/chunk caps above, and deterministic choice between validated Content-Length and final chunked coding. Save source and artifacts/8.3-framing-tests.txt. Exercise malformed framing only as static bytes, never across a network.

  • Parse headers through \r\n\r\n; reject TE+CL, conflicting/invalid lengths, unsupported transfer codings, EOF, and cap violations.
  • Test Content-Length exact/empty/truncated/extra and chunked normal/empty/bad-hex/missing-CRLF/oversized cases.
  • Connect only to 127.0.0.1/::1, record timeouts/caps, close the socket, and state why the result is not production-ready.

2. Hand-label chunked content

20 min

Save a benign chunk sequence annotation in artifacts/8.3-chunks.md.

  • Identify hex sizes/terminator.
  • State decoded length.
  • Explain why cap is required.

3. Rejection policy

20 min

Write local AbuseGuard ingress limits and log fields.

  • Save artifacts/8.3-policy.md.
  • Reject ambiguity, do not normalize.
  • State authorized test boundary.
