Practical field guide · Processes

See what the system is actually running.

Processes turn files into behavior. PID relationships, open files, network sockets, signals, and exit status let you diagnose collectors and services from evidence instead of guessing.

01 · Purpose

Why processes matter in detection work

01 · OBSERVABILITY

Behavior lives in running state

The executable on disk is only a program. The process has credentials, arguments, environment, memory, working directory, and open resources.

02 · OPERATIONS

Collectors fail as processes

Crashes, hangs, restart loops, blocked I/O, stale sockets, and leaked descriptors all leave process-level evidence.

03 · RESPONSE

Signals provide controlled intervention

A graceful termination lets a service flush buffers and remove state; a forced kill removes that opportunity.

04 · DETECTION

Parent-child context carries meaning

A shell starting a network tool may be normal administration or suspicious post-exploitation depending on ancestry, user, arguments, and host role.

The useful definitionA program is executable content on disk. A process is a running instance with a PID and kernel-managed state. Many processes may run the same program, each with different arguments and resources.

02 · Start here

Pause, continue, and stop one harmless process

A command is the request you type. A process is a running instance of a program. A shell job is the shell's handle for one pipeline, which may contain one process or several. Keeping those three words separate makes job control much easier.

sleep 300       # This process occupies the foreground.
# Press Ctrl-Z: the terminal normally sends SIGTSTP and Bash reports “Stopped”.
jobs -l         # Show this shell's jobs, states, and process IDs.
bg %1           # Continue job 1 in the background.
jobs -l
fg %1           # Bring job 1 back to the foreground.
# Press Ctrl-C: the terminal normally sends SIGINT to the foreground job.
printf 'status=%s\n' "$?"

The %1 is a shell job specification; the number shown by jobs -l is a PID. They are different namespaces. You can also start asynchronously with sleep 300 &; Bash prints a job number and PID, while $! expands to the PID of the most recent asynchronous command.

What the familiar control keys really do

Usual keyTerminal actionPractical result
Ctrl-CSend SIGINTAsk the foreground process group to interrupt. A process may handle or ignore it.
Ctrl-ZSend SIGTSTPStop the foreground process group so the shell can manage it with bg or fg.
Ctrl-\Send SIGQUITQuit by default and possibly create a core dump; this is not the normal first choice.
Ctrl-DProvide the terminal's EOF characterFinish pending input or make an empty read return end-of-file. It does not send SIGQUIT.

These are conventional terminal settings, not magic hard-coded into every program. Inspect the current mappings with stty -a.

Move from a name to evidence before sending a signal

pgrep -af analyzer
ps -o user,pid,ppid,tty,stat,lstart,args -p <pid>
kill -TERM <pid>     # Request termination; allow cleanup.
# Recheck the exact PID and state. Only if graceful handling has failed:
kill -KILL <pid>     # Forced termination; cannot be caught or ignored.
A ? in the ps TTY column has a narrow meaningIt means the process has no controlling terminal. It does not prove the kernel started the process, and it does not by itself make the process suspicious. Services, containers, scheduled tasks, and detached processes commonly have no TTY.

Verified against: the GNU Bash job-control documentation, Linux termios(3) for terminal control characters, Linux signal(7) for signal dispositions, and ps(1) for TTY and process fields.

03 · Command walkthroughs

Snapshot, monitor, match, and adjust processes

ps is a snapshot; top is a changing view

ps                         # Same user and terminal by default on procps-ng.
ps -e                      # Every process, standard option style.
ps -ef                     # Every process with full-format columns.
ps ax                      # Every process, BSD option style.
ps -p 1234 -o pid,ppid,user,tty,stat,etime,%cpu,%mem,args
ps -eo pid,ppid,user,stat,%cpu,%mem,args --sort=-%cpu | head

top                        # Interactive, implementation-specific controls.
top -b -n 1                # One batch snapshot on procps-ng/Linux.

Linux ps accepts Unix options with a dash, BSD options without a dash, and GNU long options; mixing styles can change both selection and output. For recorded evidence, choose explicit fields with -o rather than depending on a person's remembered meaning of ps aux.

FieldRead it asCommon mistake
PID / PPIDProcess identity / recorded parent identity.PIDs are reused; a number alone is not durable identity.
TTYControlling terminal, or none.? does not mean “kernel process.”
STATPrimary state plus modifiers documented by this ps.Sleeping means waiting; it does not by itself mean hung.
TIMEAccumulated CPU time.It is not the process's wall-clock age; use etime.
%CPUImplementation-defined utilization calculation.Do not assume one snapshot tells you the cause.

In Linux top, the load averages describe exponentially damped demand over roughly 1, 5, and 15 minutes; they are not “now, five minutes ago, and fifteen minutes ago.” Compare load with CPU count, runnable tasks, I/O wait, and the workload before deciding it is unhealthy.

pgrep/pkill: prove the match before acting

pgrep -af collector                    # Linux: PID plus full command line.
pgrep -u collector_user -x python3     # Exact process name for one user.
pkill -TERM -u collector_user -x python3
pgrep -u collector_user -x python3     # Verify what remains.

pgrep prints matching PIDs; pkill sends a signal to the same style of match. Match semantics, available flags, and command-name length differ by platform. Preview with pgrep, constrain by user/name/parent when possible, and avoid using a broad name as if it were a unique service identity. killall is especially non-portable: on some Unix systems its behavior is far broader than the Linux command of that name.

nice/renice: scheduling preference, not a limit

nice -n 10 ./batch-reindex.sh
renice -n 10 -p 1234
ps -p 1234 -o pid,ni,pri,%cpu,etime,args

On Linux, nice values normally range from -20 (more favorable scheduling priority) to 19 (less favorable). An ordinary user can generally increase the nice value of an owned process, but lowering it requires privilege. Nice values influence CPU scheduling contention; they do not impose a hard CPU quota and may have little visible effect when the machine is otherwise idle.

nohup: survive a hangup, not become a service

nohup ./one-off-import.sh \
  < /dev/null \
  > import.log \
  2>&1 &
import_pid=$!
printf 'pid=%s\n' "$import_pid"

nohup arranges for the command to ignore SIGHUP and may redirect terminal-connected output to nohup.out. It does not put the command in the background—the final & does that—and it provides no restart policy, health check, log rotation, dependency ordering, or boot persistence.

Verified against: Linux ps(1), procps-ng top(1) and pgrep(1), plus GNU Coreutils documentation for nice and nohup.

04 · Mental model

A process is a resource container

Program + argumentsExecutable code and the argument array selected at launch.python analyzer.py
→
Process identityPID, parent PID, user/group credentials, environment, cwd, and lifecycle state.ps -o ...
→
Open resourcesFile descriptors for files, pipes, sockets, devices, and other kernel objects.lsof -p PID

A child normally inherits environment, current directory, open descriptors, and credentials from its parent, then may replace its program image with another executable.

Identity and lifecycle fields

FieldMeaningDetection value
PIDProcess identifier, unique only while allocatedJoin point for live inspection; do not treat as durable identity.
PPIDParent process identifierBuild ancestry such as service → shell → utility.
UID/GIDEffective credentials used for access checksExplain permissions and privilege context.
StateRunning, sleeping, stopped, zombie, and platform variantsDistinguish waiting from deadlocked or unreaped behavior.
Elapsed / CPU timeWall-clock lifetime versus CPU consumedSpot restart loops or unexpectedly expensive workers.
Command / argsLaunch-time argument vector, sometimes truncated or mutableUseful signal, never a trusted security boundary.
Names can lieProcess names and command lines may be truncated, changed, or intentionally deceptive. Correlate executable path, hash/signature, ancestry, user, open connections, and observed behavior.

05 · Core working set

Inspect from broad to specific

ps aux

Snapshot all processes.Widely available BSD-style view with user, CPU, memory, and command. For scripts, select explicit columns instead.

ps -p PID -o pid,ppid,user,stat,etime,command

Inspect one process predictably.Explicit output fields are easier to record and compare.

pgrep -af pattern

Find matching PIDs and arguments.On macOS, pgrep -fl pattern is the common equivalent.

pstree -p

See ancestry as a tree.Availability varies; ps with PID/PPID remains the portable foundation.

top

Observe changing resource use.Use it to generate a hypothesis, then capture evidence with non-interactive commands.

lsof -p PID

List open resources.Shows files, cwd, libraries, pipes, and sockets associated with a process.

lsof -iTCP:8000 -sTCP:LISTEN

Find a listening process.Maps a port conflict back to PID and executable context.

Linux /proc

Linux exposes process state as a virtual filesystem. Permissions and kernel hardening can restrict what you can read. macOS does not provide Linux-style /proc; use ps, lsof, and platform tools.

pid=1234
readlink "/proc/$pid/exe"
readlink "/proc/$pid/cwd"
tr '\0' ' ' < "/proc/$pid/cmdline"; printf '\n'
ls -l "/proc/$pid/fd"
sed -n '1,25p' "/proc/$pid/status"
Environment may contain secrets/proc/PID/environ, process arguments, and debug dumps can expose tokens or credentials. Read only when authorized, minimize collection, and redact before saving or sharing.

06 · Terminal control

Foreground, background, and shell jobs

Job control is a relationship between an interactive shell, a controlling terminal, process groups, and signals. A shell job number such as %1 is not a PID.

command &

Start a background job.The shell returns a job number and PID instead of waiting in the foreground.

jobs -l

List this shell's jobs.Shows job numbers, PIDs, and stopped/running state.

Ctrl-Z

Stop the foreground job.The terminal driver normally sends SIGTSTP; the process is paused, not terminated.

bg %1

Continue a stopped job in background.Useful for interactive work, not service supervision.

fg %1

Return a job to foreground.The job regains the terminal and the shell waits for it.

wait PID

Wait and collect status.Scripts use wait to synchronize background children and observe their exit result.

Background is not a service managerAmpersand, nohup, and terminal multiplexers are useful tools, but production collectors need supervision, restart policy, logs, resource limits, identity, and dependency management from systemd, launchd, Kubernetes, or an equivalent.

07 · Lifecycle control

Signals are asynchronous notifications

SignalCommon numberIntent
SIGINT2Interactive interrupt, normally from Ctrl-C. Programs may handle it.
SIGTERM15Request graceful termination. Default first choice for stopping a process.
SIGKILL9Immediate kernel termination; cannot be caught or cleaned up.
SIGHUP1Terminal hangup; many daemons conventionally reload config.
SIGSTOP19 on LinuxUncatchable pause; number varies by platform.
SIGCONT18 on LinuxContinue a stopped process; number varies by platform.
 
kill -TERM PID
# Wait and inspect shutdown behavior before escalation:
ps -p PID -o pid,stat,etime,command

# Ask the local system for names/numbers instead of memorizing:
kill -l
SIGKILL is the last resortIt prevents cleanup handlers, buffered log flushes, transaction shutdown, temporary-file removal, and application-level state repair. If SIGTERM fails, first confirm the PID still identifies the intended process and capture evidence for why it is stuck.

08 · Outcomes

Exit status is a tiny but critical API

By convention, zero means success and nonzero means failure or another documented outcome. The shell stores the most recent foreground pipeline status in $?; read it immediately.

python3 analyzer.py access.log
status=$?
printf 'analyzer status=%s\n' "$status"
if (( status != 0 )); then
  printf 'analysis failed\n' >&2
fi
StatusCommon meaningCaution
0SuccessOnly means what that program documents as success.
1Generic false/failureSome tools use 1 for a valid “no match,” such as grep.
2 and othersProgram-specific errorRead the tool's documentation.
128 + NShell convention for termination by signal NConventions and reporting details can vary.
Automation contractA detection script should send result data to stdout, diagnostics to stderr, and a documented status to the parent. A scheduler can then distinguish “no findings” from “analysis failed.”

09 · On the job

Detection-engineering scenarios

PORT CONFLICT

The local detection API cannot bind port 8000

lsof -nP -iTCP:8000 -sTCP:LISTEN
ps -p <pid> -o pid,ppid,user,etime,command
# Decide whether it is expected before sending any signal.

Reasoning: identify the listener, owner, parent, and lifetime. Killing the first matching PID can terminate the wrong service or hide a restart loop.

HUNG COLLECTOR

A collector is alive but stops producing events

ps -p <pid> -o pid,ppid,stat,etime,time,command
lsof -p <pid>
# Linux, if authorized:
ls -l /proc/<pid>/fd

Look for: blocked pipe/socket, deleted log descriptor, stopped state, unexpected cwd, or repeated children. Capture state, request graceful termination, and observe supervisor behavior.

RESTART LOOP

The PID changes every few seconds

while sleep 2; do
  date
  pgrep -fl collector
done
# Stop the observation loop with Ctrl-C.

Interpretation: a supervisor may be repeatedly replacing a crashing process. Inspect service-manager status and logs rather than chasing each short-lived PID.

DELETED LOG

Disk remains full after a large log was deleted

lsof +L1
# Identify deleted-but-open files, then inspect the owning process.
ps -p <pid> -o pid,ppid,user,etime,command

Why: unlinking removes the pathname, but storage remains referenced until the process closes its descriptor. Coordinate a safe reload/restart instead of deleting more evidence.

10 · Practice

Hands-on drills

1. Inspect a background process

15 min
sleep 300 &
lab_pid=$!
jobs -l
ps -p "$lab_pid" -o pid,ppid,user,stat,etime,command
lsof -p "$lab_pid" | head
  • Identify the shell PID and child PPID.
  • Explain the process state and elapsed time.
  • Distinguish the job number from lab_pid.

2. Signal and collect status

15 min
kill -TERM "$lab_pid"
wait "$lab_pid"
status=$?
printf 'status=%s\n' "$status"
ps -p "$lab_pid"
  • Explain the observed status.
  • Show that the PID is no longer present.
  • Repeat with Ctrl-C on a fresh foreground sleep and compare.

3. Observe your analyzer

25 min

Run your log analyzer against a large or intentionally throttled fixture, then record its PID, PPID, executable, cwd, arguments, open input/output files, and termination status.

  • Use ps and lsof; use /proc only on Linux.
  • Send SIGTERM and verify whether output remains valid or partial.
  • Document what graceful shutdown should do in a production collector.
