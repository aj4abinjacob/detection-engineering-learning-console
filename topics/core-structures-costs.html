01 · Purpose

Cost is a reliability requirement

A parser that repeatedly inserts at the front of a list or rescans every event may look correct against a tiny fixture and fail under a real burst. Pick the representation from the operation, data volume, ordering, and retention policy.

EVENTS

Append streams

Lists are compact, fast append-oriented sequences.

GROUPING

Lookup entities

Dicts/sets give expected constant-time access.

WINDOWS

Expire oldest

Deque supports both ends without shifting a list.

RANKING

Keep only candidates

A heap avoids sorting everything for small top-N.

03 · Costs

Average operation map

StructureGood operationsTypical costChoose when
listappend, last pop, indexamortized O(1)ordered batch / append stream
listfront insert/pop, membershipO(n)not an expiry queue or frequent lookup set
tupleindex, iterationO(1) / O(n)fixed value/key, no mutation
dict/setget/add/deleteexpected O(1), worst O(n)entity lookup/dedup
dequeappend/pop at either endO(1)FIFO or sliding window
heapqpush/pop bestO(log n)bounded top-N/scheduling

“Expected” hash cost assumes well-distributed, stable hashes and non-adversarial keys. List append is amortized: an occasional resize costs O(n), spread across many appends. A deque is not a drop-in random-access list; middle access is O(n).

04 · Everyday structures

from collections import Counter, defaultdict, deque

counts = Counter(status for status in statuses)     # count hashable values
by_ip = defaultdict(list)                           # missing key gets a fresh list
by_ip["203.0.113.8"].append("r-17")
window = deque()                                    # append newest; popleft oldest

Use: Counter for counts, defaultdict for deliberate grouping, deque for both-end queues. Assumptions: counter keys are hashable; defaultdict’s factory is safe and intended. Risk: indexing by_ip[unknown] creates a new entry, potentially growing memory merely while probing. Use get() for a read-only lookup.

tuple is immutable as a container and can be a dict key only when all its members are hashable. A list/set/dict holds references to Python objects, so data locality and memory overhead differ from a packed numeric array; profile actual representations rather than importing array-language intuitions.

05 · Priority queues

import heapq
top_three = heapq.nlargest(3, counts.items(), key=lambda item: item[1])
# For streaming: retain a min-heap of at most k candidates; see Topic 4.5.

Use: heapq for a priority queue or small top-N from an iterable. Assumption: your comparison key establishes a deterministic tie policy if reports need it. Risk: a heap is only partially sorted; iterating its backing list is not rank order. Use heappop or a final sort for ordered presentation.

06 · Benchmark honestly

from time import perf_counter
from collections import deque

def elapsed(fn):
    start = perf_counter(); fn(); return perf_counter() - start
print(elapsed(lambda: [None] * 10_000))  # bounded synthetic workload

Use: compare equivalent, warmed-up operations on bounded synthetic input. Assumption: one measurement is only a local observation. Risk: do not generate giant files or extrapolate one laptop number to production. Measure multiple runs, include input size, interpreter/platform, and memory behavior; use timeit for small isolated operations.

07 · Failure and safety

Bound retention firstA correct structure still leaks memory if its retention rule is unlimited. Every per-IP dict, deque, or counter needs a maximum cardinality, expiration policy, and observability for dropped/evicted state. Attackers can intentionally create high-cardinality keys.
collections.deque(maxlen=1000)

Bound a FIFO history.Use when dropping oldest values is explicitly acceptable. Appending silently discards old values, so do not use it for evidence that must be retained.

mapping.get(key)

Probe without insertion.Use for read-only existence/lookup. It returns the provided/default value and does not call a defaultdict factory.

python -m timeit ...

Measure a tight expression.Use synthetic bounded data; shell launcher and timing precision vary by platform/version.

08 · Detection scenarios

Four choices that change production behavior

WINDOW

Login-rate detector removes oldest events

Use one deque per entity, not list.pop(0), so expiration does not shift every retained event. Add entity expiration to bound the outer dict.

FANOUT

Parser groups records by client

defaultdict(list) makes construction concise, but a unique client flood creates lists forever. Choose aggregation/limits rather than retaining every record blindly.

TOP-N

Analyst needs ten noisiest sources

Count in a dict/Counter, then choose sort or heap based on entity cardinality and whether all counts already fit in memory.

KEY

Request grouping key changes

Use immutable tuples/frozen value objects for dict keys. A mutable key changes hash/equality behavior and makes lookups unreliable (Topic 4.2).
