01 · Purpose

Abuse type is a hypothesis, not a label

The same request sequence can be accessibility software, a partner integration, a power user, an outage retry loop, or harmful automation. Start with harm/preconditions and preserve uncertainty.

HARM

State impact

Confidentiality, integrity, availability, fraud, or cost.

EVIDENCE

Separate time

Request-time facts differ from later outcomes.

CONTROL

Price friction

Every mitigation affects legitimate users.

LEARNING

Use local labels

Experiment labels exist outside client request stream.

04 · Evidence quality

Record request-time facts: timestamp, trusted tenant/client context, normalized route, authenticated state, response class, operation outcome, rate, and server resource effect. Later facts include chargebacks, verified compromise, content reuse, fulfillment, or user report. Do not retrofit delayed outcome as if it was visible in the original request.

05 · Controls are layered

Candidate controls include secure authentication/MFA, object authorization, quotas, pagination, idempotency, rate/concurrency limits, verified contact/payment flows, anomaly review, caching, and manual support paths. Choose proportionally: a hard block can exclude researchers, assistive tech, mobile clients, partners, or users behind shared networks.

06 · Delayed outcome joins

Use stable internal event/operation IDs to join later verified outcomes to earlier facts under access controls. Labels may be delayed, incomplete, and biased by who reports; measure coverage before treating them as ground truth.

07 · False-positive boundary

A fast catalog browser may be an accessibility tool; a high login failure rate may be a password-manager sync or an incident; repeated cart activity may be a test. Every candidate control needs an appeal/allowlist/support path, rollout measurement, and a human-review threshold where impact is high.

08 · AbuseGuard event

{"event_id":"lab-e13","route":"/login","outcome":"invalid_credentials",
 "rate_bucket":"ip_tenant_1m","label":"unassigned"}

Use: internal identifiers, normalized outcomes, and an unassigned label until reviewed. Risk: do not put test labels or secret control decisions in client-controlled requests; exclude passwords/payment/session values.

09 · Safety

Defensive local taxonomy onlyDo not target public sites, use real accounts/cards/credentials, or create bypass/payload instructions. Simulate only local AbuseGuard flows with synthetic principals and hard rate/resource caps.

10 · Detection scenarios

STUFFING

Failed login fan-out

Trigger: many accounts per trusted source window. Artifact: synthetic event counts. Observation: failures then a rare success. Reasoning: compatible with stuffing, also a shared test/integration. Boundary: step-up/review, not automatic compromise label.

SCRAPE

Deep product traversal

Trigger: high pagination breadth. Artifact: local route sequence. Observation: low dwell/high volume. Reasoning: possible extraction or power research. Boundary: apply quotas/caching and accessible API path before block.

INVENTORY

Reservations expire

Trigger: repeated holds without checkout. Artifact: hold lifecycle. Observation: inventory unavailable. Reasoning: possible denial-of-inventory or checkout failure. Boundary: short expiry/support investigation.

API

Costly endpoint burst

Trigger: high compute per request. Artifact: duration/cost bucket. Observation: limit rejects. Reasoning: abuse or legitimate batch. Boundary: quotas/async batch path and review.
