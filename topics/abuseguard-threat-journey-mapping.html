Practical field guide · Controlled experiments

Turn journeys into experiments with stopping rules.

A journey becomes useful training data only when it has a hypothesis, server-controlled label, variables, resource guardrails, stop condition, and saved artifact—not a vague “simulate abuse” instruction.

01 · Purpose

Controlled journeys create interpretable evidence

Five local flows let you test observability and controls without claiming real intent. The label is in the experiment manifest, never carried in an HTTP request.

HYPOTHESIS

One claim

What signal/control behavior should occur?

VARIABLES

Change one thing

Rate, path breadth, account fan-out, or outcome.

GUARDRAIL

Bound work

Local host, synthetic accounts, hard caps.

ARTIFACT

Save evidence

Manifest, sanitized events, result/limits.

02 · Experiment specification

experiment_id: lab-journey-03
hypothesis: "A bounded catalog burst raises route-breadth feature, not an intent label."
label_source: "server-controlled fixture manifest"
variables: {pages: 12, interval_ms: 500}
guardrails: {host: localhost, max_requests: 20, max_duration_s: 60}
stop_condition: "any 429/5xx, cap reached, or operator stop"
artifact: artifacts/13.3-catalog.jsonl

Use: write this before running a local synthetic flow. Risk: labels in request parameters/headers contaminate telemetry and teach the system to trust a client claim. Stop condition is mandatory, not an afterthought.

03 · Journey 1: normal account use

Hypothesis: a normal login → product view → logout establishes baseline route/order/latency. Label: fixture_normal in manifest only. Variables: one synthetic account, 2–4 requests, human-like but not claimed-human interval. Guardrails: localhost, max 10 requests. Stop: authz failure/5xx. Artifact: sanitized request/outcome JSONL and route diagram.

04 · Journey 2: bounded login-failure fan-out

Hypothesis: local invalid-credential attempts across synthetic accounts raise a fan-out feature while preserving per-account outcome. Label: fixture_login_fanout. Variables: account count and interval. Guardrails: no real credentials; ≤10 attempts; local account fixtures only. Stop: rate limit/5xx/cap. Artifact: aggregate plus raw-safe outcomes. This tests a signal, not credential stuffing capability.

05 · Journey 3: catalog breadth

Hypothesis: many distinct local product pages in a bounded interval changes breadth/velocity metrics. Label: fixture_catalog_breadth. Variables: page count/interval/cache state. Guardrails: synthetic products, ≤20 routes, max 60 seconds. Stop: cap, 429, or server error. Artifact: ordered route sequence and metrics. It is compatible with a power user; do not label it scraping in telemetry.

06 · Journey 4: reservation lifecycle

Hypothesis: local synthetic holds without checkout produce hold-create/expire facts and inventory-state metrics. Label: fixture_hold_expiry. Variables: number/duration of holds. Guardrails: fake inventory, short expiry, ≤5 holds, resettable database. Stop: cap/integrity error. Artifact: lifecycle table. This is a resilience/control test, not denial-of-inventory instruction.

07 · Journey 5: bounded costly API request

Hypothesis: a local synthetic endpoint with declared work units records cost/latency and enforces quota. Label: fixture_cost_quota. Variables: safe work-unit count under fixed cap. Guardrails: no external calls, CPU/time limit, ≤5 requests. Stop: quota/time threshold/5xx. Artifact: cost decision events. Do not create load tools or use real payment/API systems.

08 · Labels stay outside the stream

Store experiment ID/fixture label in local harness manifest or protected test database, then join to events with request IDs after collection. The application logs only facts/outcomes. This avoids an unrealistic client-provided label and makes it possible to test whether a detector would work without privileged truth embedded in traffic.

10 · Detection scenarios

BASELINE

Normal flow triggers rate feature

Trigger: baseline above threshold. Artifact: manifest/event join. Observation: ordinary journey. Reasoning: threshold too low or feature incomplete. Boundary: tune/test, do not call fixture abusive.

LABEL

Harness label leaks into event

Trigger: request has fixture header. Artifact: schema audit. Observation: label contaminates detection. Reasoning: invalid experiment. Boundary: remove it and rerun locally.

LIMIT

Cost journey gets 429

Trigger: configured quota. Artifact: decision event. Observation: limit works. Reasoning: test succeeded. Boundary: stop; never increase load to “push through.”

OUTCOME

Hold expiry looks like abuse

Trigger: repeated expiration. Artifact: lifecycle. Observation: synthetic fixture. Reasoning: tests detector/control. Boundary: label only in offline manifest.

11 · Practice

Hands-on drills

1. Five journey specs

40 min

Write all five experiment specs using the template.

  • Save artifacts/13.3-journeys.yaml.
  • Include all variables/guardrails/stops.
  • Keep labels outside requests.

2. Run normal versus fan-out locally

25 min

Use existing local AbuseGuard routes and synthetic fixtures within caps.

  • Save sanitized JSONL + manifest.
  • Stop on first limit/error.
  • Compare facts, not intent labels.

3. Artifact review

20 min

Audit one artifact for secret/label leakage and resettable state.

  • Save artifacts/13.3-review.md.
  • Prove no credentials/session IDs.
  • State rerun/reset procedure.
