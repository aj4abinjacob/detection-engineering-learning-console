01 · Purpose

Why binary literacy belongs in detection engineering

Packet captures, file uploads, telemetry agents, and protocol fingerprints arrive as octets, not Python text. If a parser silently decodes, truncates, or assumes native machine layout, it can fabricate fields or lose evidence before a detection ever runs.

FORENSICS

Bytes preserve evidence

A byte sequence has no character encoding until a format assigns one. Keep original bytes and record offsets.

PORTABILITY

Wire formats choose order

Network and file specifications define byte order; the host CPU’s order is irrelevant unless the format says native.

PERFORMANCE

Views can avoid copies

memoryview exposes a buffer window, but aliasing and lifetime become part of the contract.

SAFETY

Lengths are untrusted

Validate magic, bounds, and fixed widths before unpacking. Parsing is not permission to trust a file.

02 · Mental model

Format bytes → validate boundaries → interpret fields

A binary parser should move through declared stages. It first keeps a buffer, checks that required bytes exist, then decodes fixed-width fields with a format that names endianness. Offset arithmetic is evidence: it lets another engineer reproduce every extracted value.

Hex is a representation for people. It is not text recovered from the bytes, and it must not be fed to a parser that expects the original binary buffer.

03 · Values

str is Unicode text; bytes is octets

A Python str is a sequence of Unicode code points. A bytes object is immutable values 0–255. Encoding turns text into bytes under a named policy; decoding reverses that only when the selected encoding matches the producer.

message = "café"
wire = message.encode("utf-8", errors="strict")
print(wire)           # b'caf\xc3\xa9'
print(wire.hex())     # 636166c3a9
print(bytes.fromhex("636166c3a9").decode("utf-8", errors="strict"))

raw = b"\xff"         # valid byte, invalid standalone UTF-8 text
# raw.decode("utf-8", errors="strict") raises UnicodeDecodeError
text.encode("utf-8", errors="strict")

Encode declared Unicode text for a protocol or file.Use the encoding specified by that format. strict exposes invalid conversions; replace or ignore can irreversibly corrupt identifiers, signatures, and evidence.

data.hex() / bytes.fromhex(text)

Render or parse a human-readable hexadecimal representation.Use it in bounded diagnostics and fixtures. Hex doubles size and may expose tokens or payloads in tickets; redact and cap output.

data.decode(encoding, errors="strict")

Interpret bytes as text only after the format identifies an encoding.It assumes the field is actually textual. Never decode an arbitrary protocol buffer “just to inspect it” and then rely on altered text as evidence.

Version and platform note: this guide targets Python 3.11+ standard-library APIs; these types and UTF-8 behavior are portable across supported Python implementations. The default text encoding used by open() can depend on environment and Python UTF-8 mode, so parsers should name the format’s encoding explicitly instead of relying on a machine default.

04 · Mutability & aliasing

bytearray changes; memoryview shares

packet = bytearray(b"ABCD")
field = memoryview(packet)[1:3]  # a view, not a copy
field[0] = ord("Z")
print(packet)                    # bytearray(b'AZCD')

snapshot = bytes(packet)         # immutable copy at this moment
print(snapshot[1:3].hex())       # 5a43

A slice of bytes and bytearray creates a new object; a sliced memoryview usually aliases the same exported buffer. That can reduce copies in a controlled parser, but it means writers can change what readers observe.

Buffer lifetimeDo not resize a bytearray while a memoryview exports it: CPython raises BufferError. More importantly, do not retain a view to a reusable receive buffer after the owner refills it—the bytes may be overwritten. Copy the bounded field with bytes(view) when it must outlive the buffer or cross an ownership boundary.
def fixed_field(data: bytes, offset: int, width: int) -> bytes:
    if offset < 0 or width < 0 or offset + width > len(data):
        raise ValueError("field lies outside the supplied buffer")
    return data[offset:offset + width]  # fixed-width copy, clear ownership

05 · Binary layout

Make byte order and padding explicit with struct

struct packs and unpacks fixed-width C-like values. Its first character selects byte order, size, and alignment. Protocol parsers should virtually always select a standard, explicit order—not native layout.

PrefixMeaningUse / risk
@Native byte order, native size and alignment (default).For in-process native data only; padding and size vary by architecture/compiler assumptions.
=Native byte order, standard sizes, no alignment.Still host-endian; unsuitable for a portable wire/file format.
<Little-endian, standard sizes, no alignment.Use only when the format specifies little-endian (for example, many WAV fields).
> or !Big-endian, standard sizes, no alignment; ! means network order.Use for formats that specify big-endian/network order, including PNG integers.
import struct

FORMAT = ">IHB"  # big-endian: 4-byte unsigned int, 2-byte unsigned short, byte
WIDTH = struct.calcsize(FORMAT)  # 7, with no native padding

def unpack_header(data: bytes, offset: int = 0) -> tuple[int, int, int]:
    if offset < 0 or len(data) - offset < WIDTH:
        raise ValueError(f"need {WIDTH} bytes at offset {offset}")
    return struct.unpack_from(FORMAT, data, offset)

struct.unpack() requires a buffer exactly the format’s size. unpack_from() reads at an offset from a larger buffer, but it still raises struct.error on insufficient data. Check bounds yourself so the error can state which field and offset failed. Do not use sys.byteorder to choose a protocol order: it reports the host, not the specification.

06 · Defensive parsing

Parse a PNG IHDR header and label every offset

PNG begins with an 8-byte signature. Its first chunk has a 4-byte big-endian length, a 4-byte type, then data. An IHDR data field begins with 13 bytes: width, height, bit depth, color type, compression, filter, interlace. This parser examines only that fixed header; it does not validate the whole image or decompress anything.

import struct

PNG_SIGNATURE = b"\x89PNG\r\n\x1a\n"
IHDR_FORMAT = ">IIBBBBB"
IHDR_SIZE = struct.calcsize(IHDR_FORMAT)  # 13

def parse_png_ihdr(data: bytes) -> dict:
    if len(data) < 8 + 8 + IHDR_SIZE:
        raise ValueError("truncated before PNG IHDR")
    if data[:8] != PNG_SIGNATURE:
        raise ValueError("not a PNG signature")
    chunk_len = struct.unpack_from(">I", data, 8)[0]       # bytes 8..11
    chunk_type = data[12:16]                               # bytes 12..15
    if chunk_type != b"IHDR" or chunk_len != IHDR_SIZE:
        raise ValueError("first chunk is not a 13-byte IHDR")
    width, height, bit_depth, color_type, compression, filter_, interlace = (
        struct.unpack_from(IHDR_FORMAT, data, 16)           # bytes 16..28
    )
    if width == 0 or height == 0 or compression != 0 or filter_ != 0:
        raise ValueError("unsupported or invalid IHDR values")
    return {"width": width, "height": height, "bit_depth": bit_depth,
            "color_type": color_type, "interlace": interlace, "ihdr_offset": 16}
fixture = (PNG_SIGNATURE + struct.pack(">I", 13) + b"IHDR" +
           struct.pack(">IIBBBBB", 800, 600, 8, 2, 0, 0, 0))
print(parse_png_ihdr(fixture))
# {'width': 800, 'height': 600, 'bit_depth': 8, ... 'ihdr_offset': 16}

The offsets above are zero-based. A full PNG validator must also enforce chunk ordering, CRCs, chunk lengths, type-specific rules, and resource limits. Avoid treating a magic value as a security guarantee; file-type confusion and decompression bombs belong to a separate, bounded validation policy.

07 · Failure modes & safety

Binary data fails at boundaries

FailureCauseDefensive response
Garbled text / decode errorWrong encoding or binary field treated as text.Keep bytes; decode only fields whose encoding is specified, with strict errors.
Different results by machineNative struct layout or endianness was assumed.Use <, >, or ! from the format specification.
struct.error / bad fieldTruncated buffer or unchecked offset/length.Validate every offset and width before unpacking; cap input size.
Unexpected buffer changeA memoryview aliases a mutable/reused buffer.Document ownership; copy values that must persist.
CPU or memory denial of serviceAttacker-controlled lengths cause allocation, recursive parsing, or decompression.Set per-format length, nesting, time, and output limits before deeper parsing.

08 · On the job

Detection-engineering scenarios

UPLOAD

Image upload claims to be a PNG

Log the signature, IHDR offsets, dimensions, and parser failure reason from a bounded prefix. Do not trust an extension or magic alone; route full validation and content handling through the approved upload pipeline.

TELEMETRY

Agent parser reports wildly different counters

Compare the wire specification with the struct prefix. Native @ padding or host endian assumptions can shift offsets, turning one field into another. Add a fixture whose expected hex and offsets are reviewed.

FORENSICS

Analyst needs a shareable packet fragment

Save only a minimal authorized, redacted hex window plus its byte offsets and parser version. A hex dump can still contain identifiers, cookies, or payload data; access control and retention policy apply.

PIPELINE

Reusable receive buffer corrupts queued events

A queue receives memoryviews of a buffer that the reader refills. Enforce buffer ownership: copy the bounded record before enqueueing, or transfer a buffer that will not be reused until consumers finish.

09 · Practice

Hands-on drills

1. Record text and hex evidence

20 min

In artifacts/binary/, create encoding.py and encoding-transcript.txt. Encode a non-ASCII string as UTF-8, display hex, reconstruct it, and show one strict-decode failure using a synthetic byte.

  • Name the encoding and error policy.
  • Explain why hex is not decoded text.
  • State why ignore would weaken evidence integrity.

2. Prove aliasing and ownership

20 min

Save views.py and views-transcript.txt. Modify a bytearray through a memoryview, then make an immutable bytes snapshot and show which values change.

  • Identify which operations copy and which alias.
  • Demonstrate a checked fixed-width slice.
  • Describe when a view must be copied before queueing or storing.

3. Build the PNG IHDR parser from blank

40 min

Save png_header.py, a synthetic fixture.png-prefix.hex, and offset-report.md. Parse width, height, bit depth, color type, compression, filter, and interlace without third-party libraries.

  • Label zero-based offsets 0–7, 8–11, 12–15, and 16–28.
  • Use calcsize and explicit big-endian format strings.
  • Include truncated, wrong-signature, and wrong-IHDR-length tests.
