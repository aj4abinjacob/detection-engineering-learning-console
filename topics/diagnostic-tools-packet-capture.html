Networking

Use each diagnostic tool for the fact it can actually establish.

Ping, traceroute, DNS queries, socket tools, and packet capture offer bounded evidence. A capture is sensitive collection: use only authorized learner-owned loopback/local traffic with a narrow interface, filter, duration, and stop condition.

Why it matters

Diagnostics reduce uncertainty only when the tool, collector position, protocol, and time window match the claim. None of these tools proves application intent or maliciousness alone.

What tools prove

Tool Useful evidence Does not prove
ping ICMP response/path reachability under policy TCP/HTTP health; silence may be filtering
traceroute TTL-expiry responders on a path sample Full/return path or ownership
dig/nslookup Chosen resolver response Global DNS/app connection
ss/lsof Local sockets/process associations Remote application intent
tcpdump/Wireshark Packets at capture point All network traffic or encrypted content

Reachability commands

ping -c 3 127.0.0.1
traceroute 127.0.0.1

Examples are syntax only; do not run network diagnostics for this task. Linux/macOS/BSD flags differ: macOS/BSD uses ping -c; Windows uses ping -n and tracert. Use loopback/authorized targets and bounded counts. ICMP may be rate-limited or filtered.

Local sockets

ss -ltn; lsof -nP -iTCP -sTCP:LISTEN

ss is common Linux; macOS/BSD use netstat/lsof; Windows offers netstat -ano and PowerShell Get-NetTCPConnection. These list local kernel state and sometimes process ownership depending on privilege; they do not inspect remote systems.

Capture only with explicit scope

sudo tcpdump -i lo0 -c 20 -w loopback.pcap 'tcp port 8000'
# Press Ctrl-C immediately if the declared count/traffic does not behave as expected.

This is a macOS-style syntax illustration only: Linux loopback is often lo, BSD/macOS syntax/options vary, and Windows commonly uses Wireshark/Npcap. Use exactly one owned interface, a narrow local filter, short count/duration, saved path, and explicit stop. sudo or packet capabilities expose traffic from other processes; never capture a shared/real network for practice.

Read saved, sanitized evidence

Wireshark display filters select packets after capture; capture filters limit collection. For an authorized local PCAP, isolate DNS, TCP handshake flags, and start of TLS, then annotate direction/time/tuple. TLS encrypts content after handshake boundaries; avoid exporting payloads, cookies, names, or tokens.

Platform and version caveats

Tool availability, permissions, interface names, DNS resolver behavior, and output columns vary across Linux distributions, macOS/BSD, and Windows. Run tool --help locally before use; do not copy GNU-only flags to BSD/macOS. Current DNS/routing output is network-dependent evidence, not a timeless fact.

Privacy and stopping rule

Before a capture, obtain authorization, select owned loopback/local traffic, name the interface/filter/count/output owner, and decide how to stop. Stop at count/time; inspect and sanitize before sharing; restrict access and retention. No promiscuous collection, scanning, external target exercise, or long-running capture belongs here.

Detection scenarios

Service cannot bind port

Use local socket evidence to find listener/ownership; it does not diagnose remote reachability.

DNS lookup disagreement

Record resolver, type, time, cache context, and split-horizon possibility.

Handshake versus application failure

Authorized local PCAP can show SYN/SYN-ACK/ACK, not valid application authentication.

Route alert

Traceroute responders are a sampled forward path; do not infer full route/control.

Saved-evidence drills

1. Tool capability table

Save artifacts/diagnostics/tool-limits.md.

  • List what ping/traceroute/dig/socket tools prove.
  • List one limit each.

2. Make one bounded learner-owned capture

First save capture-plan.md naming authorization, owned interface, exact host/port filter, maximum 100 packets or 30 seconds, output owner, and Ctrl-C stop. Then capture one request to a learner-owned local HTTP/TLS lab service (or use an instructor-provided sanitized PCAP if privilege is unavailable) and stop at the declared bound.

  • Name interface, capture filter, packet/time cap, start, and explicit stop.
  • Never use a broad shared interface, promiscuous practice capture, or a third-party site.
  • Restrict and delete the raw PCAP under the written retention policy after deriving sanitized evidence.

3. Annotate DNS, TCP, and TLS boundaries

Save packet-annotation.md plus sanitized screenshots/packet numbers from the owned capture or supplied PCAP.

  • Mark any DNS lookup, SYN/SYN-ACK/ACK, and the start of TLS; if one is absent, explain why.
  • Record direction, tuple, capture point, timing, and what encrypted content remains unavailable.
  • Remove payloads, cookies, hostnames, addresses, and unrelated packets before sharing.
