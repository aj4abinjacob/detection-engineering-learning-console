Choose primitives by security goal, and keep secrets out.

CSPRNG, KDF, MAC, signatures, encryption, and AEAD solve different problems. Correct primitive choice does not compensate for leaked keys or invented protocol design.

Why it matters

“Encrypt it” is not a requirements statement. Name secrecy, integrity, authenticity, password resistance, or unpredictable generation, then use reviewed library APIs and protocols.

CSPRNG

import hashlib, secrets

raw_token = secrets.token_urlsafe(32)       # send once over protected channel
stored_digest = hashlib.sha256(raw_token.encode()).digest()  # store for lookup
# Enforce purpose, account binding, expiry, and single use in server state.

Use an OS-backed CSPRNG such as Python secrets for session/reset tokens. Do not use random for security. The example's digest limits direct recovery if this lookup column leaks, but token entropy, lifecycle, rate limits, and constant-time verification still matter.

Password KDF

Argon2/pwdlib derives expensive verifiers for passwords; it is not a general file-encryption key recipe. Never create custom salting/hashing scheme.

MAC

A MAC proves integrity/authenticity to parties sharing secret key. It does not provide confidentiality or public verification. Compare MACs with library constant-time verification APIs.

Digital signatures

Private key signs; public key verifies. Signatures provide authenticity/integrity under key policy, not secrecy. Validate algorithm/key/format through a reviewed protocol.

Encryption and AEAD

Encryption provides confidentiality; AEAD also authenticates ciphertext and associated data. Nonce/key management is critical; use a vetted library/protocol and never reuse nonce contrary to algorithm requirements.

Secret handling

Use a deployment secret manager or narrowly injected configuration with least privilege; environment variables can still leak through process dumps, diagnostics, or child processes. Redact logs/errors; exclude local .env and generated keys from Git; keep a committed .env.example containing names only; rotate/revoke under policy. Hashes, tokens, ciphertext, nonces, and key identifiers can still be sensitive evidence.

Safety

Use dummy values only. Do not generate or commit real long-lived keys. Algorithm recommendations/library versions change: pin dependencies and defer protocol choices to current approved standards rather than homemade crypto.

Defensive scenarios

Reset token

Use CSPRNG, expiry, single use; do not use password hash or predictable random.

Webhook integrity

Use documented MAC verification and secret rotation; encryption is not required solely for integrity.

Signed artifact

Signature verifies origin key policy, not whether content is benign.

Secret in debug log

Redact/remove/restrict according to response policy and add test.
