Understand names, delegation, and cache evidence before interpreting DNS.

DNS maps names through delegated zones and cached resolver responses. Classic DNS metadata is often observable; DoH/DoT shift visibility and collector placement.

Why it matters

DNS is a name-resolution protocol, not a proof that a connection or malicious action happened. Resolver logs, endpoint telemetry, and passive traffic each answer different questions.

Resolver model

→
Recursive resolver Uses cache or follows delegation.
→
Authority Answers for a zone.

Root, TLD, authoritative

Sanitized illustrative cache miss for api.example.com A
stub → recursive       query api.example.com A (RD=1)
recursive → root       query api.example.com A
root → recursive       referral: com. NS (+ glue where required)
recursive → com TLD    query api.example.com A
TLD → recursive        referral: example.com. NS
recursive → authority  query api.example.com A
authority → recursive  answer: 192.0.2.44, TTL 300, AA=1
recursive → stub       cached answer, RA=1

This is a teaching transcript, not current data for example.com. For an uncached name, a recursive resolver follows referrals from root to TLD to the delegated authority; a referral places NS data in the authority section and may include address “glue” needed to reach an in-bailiwick nameserver. The final authoritative response places requested data in the answer section. Clients normally ask a recursive resolver with recursion desired, not root servers directly; a cache hit can skip the external chain.

Record types

Type Meaning
A IPv4 address
AAAA IPv6 address
CNAME Alias to another canonical name
MX Mail exchanger
TXT Text data with application-specific meaning

When reading a response, preserve the question name/type/class, header flags (QR, AA, RD, RA), response code, and answer/authority/additional sections. NOERROR with no requested-type answer can be NODATA, while NXDOMAIN says the queried name does not exist. A CNAME redirects name resolution and normally cannot coexist with other data at the same owner name; follow the chain under loop/depth limits. TXT is not automatically trustworthy policy evidence—interpret it under its application specification.

Caching and negative answers

TTL controls cache lifetime, not a guarantee every resolver behaves identically. NXDOMAIN means the queried name does not exist in the relevant zone; NODATA means name exists but requested type has no data. Negative caching follows SOA-related policy. Save query type, resolver, response code, TTL, and time.

Names are scoped by zones

Authoritative does not mean globally benevolent; it means designated to answer for a zone. Split-horizon DNS, search suffixes, captive portals, and local overrides can yield different answers by network.

Visibility under encryption

Traditional UDP/TCP DNS can expose query metadata to local/on-path observers. DoT encrypts DNS transport; DoH carries DNS in HTTPS. The configured resolver still sees queries, while a passive network observer’s visibility changes. Do not infer “no DNS” merely from encrypted traffic.

Safe interpretation

dig example.invalid A; nslookup example.invalid

These commands make network queries and answers are current/network-dependent; do not run them for this guide. On Windows use nslookup or PowerShell Resolve-DnsName; macOS/Linux commonly have dig. They show a resolver answer, not global truth or an application connection.

Detection scenarios

Rare-domain alert

Confirm query type, resolver scope, cache effects, and endpoint process before attribution.

DNS outage

Distinguish NXDOMAIN, timeout, resolver failure, and application cache behavior.

DoH rollout

Passive DNS coverage changes; use endpoint/resolver telemetry instead of declaring activity absent.

CNAME chain

Record final data and chain; an alias is not a direct connection record.

Saved-evidence drills

1. Trace an authorized name resolution

For a domain you own/control or an instructor-provided lab zone, run a bounded dig +trace name.example or inspect a supplied transcript and save artifacts/dns/resolution.md. A live trace contacts public DNS infrastructure and reveals the queried name/source; obtain authorization and do not use a third party's target.

  • Draw stub/resolver/root/TLD/authority and distinguish a trace from the normal recursive-client path.
  • Record command, name, time, network/resolver context, referrals, and final response.
  • Mark cache-dependent evidence and what the result cannot prove.

2. Record table

Save record-types.md with synthetic examples.

  • Explain A/AAAA/CNAME/MX/TXT.
  • Include query type.

3. Capture one owned DNS lookup

Using the bounded capture plan from Topic 7.5, capture exactly one classic DNS lookup for your lab zone on an owned host/network, then stop and save a sanitized annotation in dns-visibility.md. If the host uses DoH/DoT or capture permission is unavailable, use a supplied sanitized PCAP and document the visibility difference.

  • Record capture point, resolver IP, query type/name, response code, and stop condition.
  • Compare classic DNS, DoT, and DoH without claiming encrypted payload visibility.
  • Remove unrelated packets and sensitive names before sharing.
