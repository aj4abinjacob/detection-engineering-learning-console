01 · Purpose

A fingerprint is a lossy feature

Fingerprints support grouping and investigation when paired with context. They collapse protocol detail, can collide/change, and may be altered by an intermediary before observation.

METHOD

Know inputs

Each method uses a specific protocol observation.

POINT

Know peer

Client→edge and proxy→origin differ.

VERSION

Know implementation

Parser/spec output can change.

LICENSE

Know permission

JA4+ licensing is per method.

02 · JA3 inputs

JA3 serializes selected ClientHello fields—SSL/TLS version, cipher suites, extension types, elliptic curves/supported groups, and EC point formats—after excluding GREASE values, then commonly MD5-hashes the string. It does not include every extension’s data/order, application behavior, peer identity, or server response. Preserve raw normalized string and parser version; hash is only a compact lookup key.

03 · JA3 weaknesses

Different clients can collide on selected fields; one client can legitimately change across OS/library/version/config; TLS 1.3/extension behavior and GREASE complicate stability; an intermediary can terminate/reissue a new handshake. MD5 use here is a historical compact identifier, not a security integrity claim. Never treat a JA3 match as proof of malware, browser identity, or intent.

Exact field encodings/submethod names evolve in the FoxIO specifications and implementations. Before use, record exact method/spec revision, parser/implementation commit/version, input source, observation role, normalization, and applicable license; do not invent a “JA4+ value” from a blog summary.

05 · Observation points

JA4 observes a TLS ClientHello only where TLS is available. JA4H requires decoded HTTP at its parser. JA4T/JA4TS characterize the TCP peer visible to the sensor, which can be a CDN/proxy rather than end user. JA4L depends on its defined measurement method and topology. A single connection may yield several fingerprints from different hops; store direction and roles.

06 · License is per method

The JA4 TLS-client method has its own permissive LICENSE-JA4; other JA4+ methods use the repository’s separate license. Verify the exact method, implementation, repository revision, and license text before redistributing, embedding, or commercial use. This guide does not provide legal advice or assume one license covers the family.

07 · uTLS is not a fingerprint algorithm

uTLS is a BSD-licensed Go TLS fork/library for ClientHello mimicry and fingerprint resistance. It is not an alternative JA3/JA4 algorithm. In a learner-owned loopback lab, you may inspect documented configuration, change a local client offer, and measure the resulting owned capture; do not use it against third parties or as a bypass recipe. Measurement may show difference, not proof it “imitates” a target client.

08 · Evidence record

{"method":"JA4","spec_revision":"recorded","implementation":"recorded",
 "license":"LICENSE-JA4 checked","point":"loopback client-to-local-terminator",
 "capture":"sanitized-owned","label":"offline fixture only"}

Use: bind every computed output to provenance. Risk: do not expose raw capture/session identifiers or place fixture label inside protocol request fields.

09 · Safety

Inspect/change/measure only in owned loopbackUse synthetic/owned captures and a localhost listener you control. No vendor testing, public connections, shared-interface capture, fingerprint evasion, or claims of identity from any output.

10 · Defensive scenarios

COLLISION

Different clients share JA3

Trigger: same hash. Artifact: raw field strings. Observation: selected inputs overlap. Reasoning: collision/legitimate convergence. Boundary: no common-client identity label.

UPDATE

JA4 changes after library update

Trigger: output drift. Artifact: owned before/after capture metadata. Observation: offer changed. Reasoning: version/config likely. Boundary: investigate deployment first.

PROXY

Origin’s TLS feature clusters

Trigger: uniform JA4. Artifact: topology. Observation: proxy terminates TLS. Reasoning: proxy offer observed. Boundary: cannot infer client type.

LICENSE

Team adopts “JA4+” library

Trigger: dependency request. Artifact: method/license matrix. Observation: per-method terms differ. Reasoning: legal/implementation review needed. Boundary: no blanket license assumption.
