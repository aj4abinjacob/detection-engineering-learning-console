Python internals II · behavioral proof

Prove the analyzer’s behavior at its useful boundaries.

01 · Purpose

A test is a small, executable evidence record

Detection code makes decisions at edges: timestamp windows, parser rejection, threshold comparisons, and storage failures. Tests preserve those intended decisions through refactors and help an investigator distinguish a regression from an undocumented assumption.

CONFIDENCE

Examples pin behavior

A clear expected result says what the rule means at a particular boundary.

ISOLATION

Fixtures name setup

Input, clock, filesystem, and client dependencies become visible rather than ambient global state.

FAILURE

Bad input is behavior

A parser’s error message and exit outcome deserve tests, not only the happy path.

SIGNAL

Coverage is a map

High coverage can still miss assertions, integrations, or adversarial data; use it to ask where evidence is absent.

02 · Mental model

Arrange explicit state, act once, assert observable behavior

ArrangeFixture creates synthetic, known state.event_factory
→
ActCall one boundary or workflow.parse(line)
→
AssertCheck output, effect, or declared error.raises(ValueError)

A test should fail for one understandable reason. Avoid test assertions that merely repeat the implementation or depend on incidental dict order, wall-clock time, external services, or a developer’s local files.

03 · Test shape

Give names to expected behavior

# tests/test_parser.py
from analyzer.parser import parse_status

def test_parse_status_accepts_three_digit_success() -> None:
    assert parse_status("200") == 200

def test_parse_status_rejects_out_of_range_code() -> None:
    import pytest
    with pytest.raises(ValueError, match="three-digit HTTP status"):
        parse_status("999")
python -m pytest -q

Collect and run the project tests through the active Python environment.Use it in local and CI commands so the interpreter is unambiguous. Exit code 0 means all selected tests passed; 1 means failures; other nonzero codes can indicate collection, usage, interruption, or internal errors—inspect the report.

pytest -k expression

Select tests by name expression while diagnosing.Use for focused iteration, then run the full intended suite. It can skip the regression you needed to detect, so do not treat a selected pass as release evidence.

pytest -x

Stop after first failure.Use to shorten a local feedback loop. It hides later independent failures, so rerun normally before handoff.

04 · Setup lifecycle

Fixtures make dependencies explicit and scoped

import pytest

@pytest.fixture
def access_lines() -> list[str]:
    return ["2026-01-01T00:00:00Z|198.51.100.8|401", "2026-01-01T00:00:01Z|198.51.100.8|200"]

@pytest.fixture
def temp_rules(tmp_path):
    rule_file = tmp_path / "rules.json"
    rule_file.write_text('{"limit": 3}', encoding="utf-8")
    return rule_file

def test_input_is_reusable(access_lines: list[str]) -> None:
    assert len(access_lines) == 2

The default fixture scope is function: each test gets a fresh instance, ideal for mutable state. module, package, session, and class can reduce expensive setup but risk state leakage. Yield fixtures provide cleanup after the test; keep cleanup targeted to tmp_path or resources the test created.

05 · Decision tables

Parametrize distinct cases with readable IDs

import pytest
from analyzer.parser import parse_status

@pytest.mark.parametrize(
    ("raw", "expected"),
    [("200", 200), ("404", 404), ("503", 503)],
    ids=["success", "not-found", "server-error"],
)
def test_parse_status_valid(raw: str, expected: int) -> None:
    assert parse_status(raw) == expected

@pytest.mark.parametrize("raw", ["", "20", "abc", "999"], ids=["empty", "short", "text", "range"])
def test_parse_status_invalid(raw: str) -> None:
    with pytest.raises(ValueError):
        parse_status(raw)

Use parameters when cases share the same behavior shape. IDs make CI failures searchable and explain the case without reading tuple positions. Avoid parameterizing unrelated stories just to reduce line count; a small named test can carry a better assertion and failure explanation.

06 · Test layers

Keep unit and integration claims different

LayerProvesDoes not prove
UnitA parser, classifier, or window function handles controlled inputs quickly.Real file encoding, database permissions, collector schema, or deployment wiring.
IntegrationSeveral owned components obey a boundary together: CLI → file → parser → output.Every external provider’s production behavior or capacity.
Contract / fixture corpusKnown producer examples retain their agreed shape.Unknown future variants; update deliberately when the producer changes.
End-to-endSelected deployed path works with controlled environment dependencies.Root cause when it fails; keep lower-layer tests for diagnosis.

Use synthetic or sanitized fixtures. Do not let unit tests call a live production API, scan an arbitrary home directory, or require a developer’s credentials. Mark deliberate integration tests and give their required services a controlled, disposable endpoint.

07 · Failure paths

Test the error contract, not only that “an exception happened”

import pytest
from analyzer.parser import parse_line

def test_parse_line_reports_line_number_for_bad_input() -> None:
    with pytest.raises(ValueError, match=r"line 7: expected timestamp\|ip\|status"):
        parse_line("broken", line_number=7)

def test_cli_returns_nonzero_for_missing_file(tmp_path) -> None:
    from analyzer.cli import main
    assert main([str(tmp_path / "missing.log")]) != 0

Exercise malformed, empty, boundary, permission/IO (with a fake or temporary path), and downstream error cases. Assert the stable behavior callers need: an exception type/message category, error result, exit status, cleanup, or an emitted safe record. Do not freeze incidental traceback line numbers or OS-specific strerror text.

08 · Repeatability

Eliminate hidden clocks, randomness, and state

Pass a clock/time value, seed or inject a random generator, use tmp_path, and isolate module/global state. Network timing, locale, process order, filesystem case behavior, and Windows file locks can make a test nonportable. State Python and pytest versions in CI; pytest plugins and assertion rewriting behavior can change across versions.

# Coverage is a question, not a target.
python -m pytest -q
python -m coverage run -m pytest
python -m coverage report -m

Coverage measures executed lines/branches under the suite. It does not measure assertion quality, threat coverage, real data diversity, or the reliability of an external integration. Use an uncovered error branch to propose a test; do not add vacuous tests to inflate a percentage.

09 · On the job

Detection-engineering scenarios

RULE QA

Threshold boundary changes from ≥ to >

Parametrize counts immediately below, exactly at, and above the threshold. The test names turn a subtle rule decision into reviewable evidence before a false-negative reaches a dashboard.

PARSER

Collector format adds a nullable field

Extend a sanitized fixture corpus with absent, null, and normal cases. Unit-test the parser’s error policy and add an integration test that proves the CLI preserves parse-reject reporting.

OUTAGE

Database adapter errors are swallowed

Use a fake adapter that raises a declared exception; assert the analyzer emits a safe error and returns the expected failure status. A unit test should not require a real outage to prove this.

FLAKE

Rate-window tests fail at midnight

Inject timestamps and normalize timezone rather than calling now(). The failed test is a modeling clue about time ownership, not a reason to add retries.

10 · Practice

Hands-on drills

1. Create a 20-test analyzer plan

35 min

Save artifacts/tests/test-plan.md and test_parser.py. Plan at least 20 meaningful tests across normal, boundary, malformed, empty, and integration behaviors; implement the parser decision table first.

  • Each proposed test names the behavior and layer.
  • Include at least three failure paths with expected error behavior.
  • Explain why a high count alone does not prove quality.

2. Fixture lifecycle evidence

25 min

Save test_fixtures.py and fixture-transcript.txt. Build a function-scoped mutable fixture and a yield fixture using tmp_path.

  • Show that mutation in one test does not reach another.
  • Show setup and cleanup only touch test-owned files.
  • State why a session fixture would change the risk.

3. Test a CLI failure and integration path

35 min

Save a tiny synthetic log, test_cli.py, and pytest-output.txt. Assert a good file produces a report and a missing/malformed file returns the documented nonzero result.

  • Run both a focused selector and the whole suite.
  • Capture pytest version and exit behavior.
  • Keep fixtures sanitized and local to the artifact directory.
