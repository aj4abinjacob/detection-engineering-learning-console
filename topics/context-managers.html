Practical field guide · Production Python

Make cleanup happen even when the analysis fails.

A context manager encodes acquire/use/release as one operation. It closes files, returns connections, restores state, and records timings without depending on garbage-collection timing.

01 · Purpose

Why deterministic cleanup matters

A long-running collector can hold file descriptors, database connections, locks, temporary artifacts, and tracing spans. If cleanup depends on the interpreter eventually destroying an object, incidents turn into descriptor leaks and stuck resources.

EVIDENCE

Flush and close safely

Files and capture writers need a defined lifetime, especially on errors.

CAPACITY

Return scarce resources

Connection pools and semaphores must be released under all ordinary exits.

OBSERVABILITY

Measure a scope

A timer around one parse or rule evaluation yields a meaningful latency boundary.

CORRECTNESS

Preserve original errors

Cleanup must not accidentally tell Python that a failed operation succeeded.

Conceptually, with is a carefully defined try/finally. The exit method receives exception information when the body fails; returning a truthy value suppresses that exception.

03 · Protocol behavior

Know what __exit__ is being asked

class TraceScope:
    def __enter__(self):
        print("enter")
        return self
    def __exit__(self, exc_type, exc, traceback):
        print("exit", exc_type.__name__ if exc_type else "success")
        return False  # False/None: propagate any body exception

with TraceScope():
    raise ValueError("lab failure")

Use: return False (or None) as the safe default. Assumption: cleanup itself can complete. Risk: returning True suppresses the body exception; use that only for a narrowly documented recovery policy and record the event.

04 · Class-based form

Use a class when the manager owns meaningful state

from pathlib import Path

class EvidenceWriter:
    def __init__(self, path: Path) -> None:
        self.path = path
        self._handle = None
    def __enter__(self):
        self._handle = self.path.open("x", encoding="utf-8")
        return self._handle
    def __exit__(self, exc_type, exc, traceback):
        assert self._handle is not None
        self._handle.close()
        return False

with EvidenceWriter(Path("artifact.json")) as output:
    output.write('{"run":"lab"}\n')

Use: a class for configurable state, reusable helpers, or multiple resource methods. Assumption: "x" exclusive-create is the desired no-overwrite policy. Risk: it raises FileExistsError if the artifact exists; that is safer for evidence, but choose a unique disposable path rather than changing to destructive overwrite.

Built-in file objects already implement this protocol, so prefer with path.open(...) unless the wrapper adds a real policy such as atomic output, auditing, or domain-specific validation.

05 · Generator form

Use @contextmanager for one simple acquire/release pair

from contextlib import contextmanager
from pathlib import Path

@contextmanager
def opened_text(path: Path):
    handle = path.open(encoding="utf-8")
    try:
        yield handle
    finally:
        handle.close()

with opened_text(Path("access.log")) as handle:
    first_line = next(handle)

The decorated generator must yield exactly once. Code before yield acquires; code in finally releases whether the body succeeds or raises. It is concise for a single scope; use a class when state or several methods would make the generator opaque. Never catch an exception around yield and fall through silently: that suppresses the body failure.

06 · Reusable timing scope

Time elapsed work with a monotonic clock

from contextlib import contextmanager
from time import perf_counter

@contextmanager
def timed(label: str, emit):
    started = perf_counter()
    try:
        yield
    finally:
        elapsed_ms = (perf_counter() - started) * 1_000
        emit({"event": "timing", "label": label, "elapsed_ms": round(elapsed_ms, 3)})

with timed("parse_batch", print):
    parse_batch(records)  # timing emits even if parsing raises

Use: perf_counter() for elapsed duration; it is monotonic and high-resolution where available. Assumption: the supplied emitter is safe and fast enough for this path. Risk: do not use elapsed timer output as wall-clock event time, and do not let a telemetry emitter exception replace the analysis exception without an explicit policy.

Timing is evidence, not a verdictRecord label, count, version, and controlled dimensions beside latency. A slow batch can be input size, downstream I/O, CPU pressure, or a regression; the scope only proves elapsed time for the chosen boundary.

07 · Async boundary

Async resources use async with

async with client.stream("GET", url) as response:
    async for line in response.aiter_lines():
        process(line)

An asynchronous context manager implements __aenter__ and __aexit__, awaited by async with. Do not use ordinary with for an async-only resource, and do not block the event loop with slow synchronous cleanup. Specific client/library lifecycle guarantees vary; consult that library’s current documentation and keep cancellation behavior visible rather than broadly suppressing it.

08 · Failure and safety

Cleanup is not permission to hide failure

with open(path, encoding="utf-8") as handle:

Open and deterministically close text input.Use for bounded local files. It assumes decoding policy is correct; malformed/hostile input can still raise while reading.

return False

Propagate a body exception from __exit__.Use as default. A truthy return means “I handled it,” a strong operational claim.

time.perf_counter()

Measure elapsed duration.Use for profiling scopes. It is not comparable across machines/processes as an absolute timestamp.

Do not suppress accidentallyA broad except Exception: pass in an exit path, or returning True because cleanup completed, transforms a failed detection into apparent success. If a cleanup error is secondary, log it safely while preserving the primary failure according to an explicit policy.
Implementation and platform notewith gives deterministic protocol calls in supported Python implementations; it does not make external writes transactional or guarantee a network peer accepted data. File locking, rename, deletion, and close semantics vary across filesystems and Windows/POSIX. Test the exact resource and deployment platform.

09 · On the job

Detection-engineering scenarios

ROTATION

A collector leaves log descriptors open after parser failures

Wrap each input handle in with. When parsing raises, close still occurs, allowing log rotation and preventing gradual descriptor exhaustion. The parse failure should propagate or be reported by a higher boundary.

POOL

A lookup worker exhausts database connections

Use the driver’s documented connection/transaction context manager so each completed or failed lookup returns the connection. Do not invent a generic wrapper without checking whether it commits, rolls back, or closes on exit.

LATENCY

A rule suddenly takes 20× longer

Place a monotonic timer around parse, enrichment, and rule scopes; emit sanitized dimensions such as record count and rule version. Compare like with like before attributing the slowdown.

EVIDENCE

An error path writes a partial report as if complete

Write to a uniquely named temporary artifact, validate/flush it, then use a platform-appropriate atomic publication strategy. A context manager closes the handle but does not by itself make the report valid or publication atomic.
