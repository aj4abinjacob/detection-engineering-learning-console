Practical field guide · Filesystem

Know what a path really names.

Paths, inodes, links, ownership, and permission bits decide whether a collector can read telemetry, whether a script can execute, and whether sensitive evidence is exposed.

01 · Purpose

Why filesystems matter in detection work

Every log, rule, socket, executable, configuration file, and investigation artifact is reached through filesystem semantics.

01 · TELEMETRY

Collectors need the right access

A process can exist and still miss events because it cannot traverse a directory or read the rotated log it was given.

02 · EVIDENCE

Paths preserve provenance

Absolute paths, hashes, metadata, and controlled permissions help another analyst reproduce where an artifact came from.

03 · DEPLOYMENT

Rules are files in motion

Symlinks and atomic renames can switch a validated rule bundle without exposing a half-written version.

04 · SECURITY

Permissions are enforcement

Misowned configs, writable executable directories, and world-readable case data are concrete privilege and confidentiality failures.

The useful definitionA pathname is a route through directory entries. The final entry names a filesystem object represented by metadata plus content. The pathname is not the file's identity.

02 · Start here

Know where you are before changing anything

A file manager and a shell can point at the same place. The file manager shows folders as pictures; the shell uses pathnames. Your first habit is to ask “where am I?” and “what is here?” before you move, copy, or remove anything.

pwd            # Print the shell's current working directory.
ls             # List the current directory.
ls -la         # Include dot-prefixed names and use a long listing.
cd Documents   # Move to a child directory, relative to where you are.
cd ..          # Move to the parent directory.
cd -           # Return to the previous working directory.
cd             # With no argument, Bash goes to your home directory.

A small path compass

FormStart lookup fromPlain-language meaning
/var/log/app.logThe process's root directoryAn absolute path: begin at / and follow every component.
logs/app.logThe current working directoryA relative path: begin where the process is now.
.Current lookup directory“This directory.” Useful in paths such as ./script.sh.
..Current lookup directory“The parent.” At the root, /.. still resolves to /.
~Expanded by the shell firstYour home directory in common interactive shells. It is shell syntax, not a literal top-level directory.

A leading / is the easiest test: present means absolute; absent means relative. Tab completion can finish a unique component, but it does not prove that you chose the intended path. Run pwd and ls again after moving.

Create a harmless lab and inspect every result

mkdir -p shell-lab/reports
cd shell-lab
touch 'case notes.txt'
ls -la
stat -- 'case notes.txt'
touch -- 'case notes.txt'
stat -- 'case notes.txt'
  1. mkdir -p creates missing parents. It also succeeds when the requested directories already exist, unless another error occurs.
  2. touch is mainly a timestamp tool. GNU touch creates an empty file only when the named file is absent and creation has not been disabled.
  3. Quotes keep spaces inside one argument. Without quotes, case notes.txt becomes two arguments.
  4. -- ends option parsing when a utility supports it. This helps with names beginning with -, but quoting is still needed for whitespace and shell metacharacters.
Names are less universal than they lookA leading dot makes a name hidden from ordinary ls output by convention; it is not an access-control boundary. Maximum component length, allowed bytes, Unicode handling, and case sensitivity depend on the filesystem and mount. Do not assume every Linux filesystem—or every macOS volume—behaves exactly like the tutorial machine.

Verified against: Linux path_resolution(7) for absolute and relative lookup plus ./.., GNU ls(1) for dot-prefixed entries, and GNU touch(1) for creation and timestamp behavior.

03 · Command walkthroughs

List, create, copy, move, and remove

Use the same loop for every file command: state the source, state the destination, predict the result, run it, and inspect both places. The command returning no text is never a reason to skip the inspection.

ls: list names and selected metadata

ls                       # Current directory, ordinary names only.
ls -la                   # Long format, including dot-prefixed names.
ls -lh -- /var/log       # Human-readable sizes in a long listing.
ls -ld -- /var/log       # The directory entry itself, not its contents.
ls -li -- rules/current  # Include inode numbers.
ls -lt -- reports        # Sort newest modification time first.
OptionWhat it changesWhat it does not mean
-aDo not ignore names beginning with .; includes implied . and ...Those names are not more private or protected.
-ALike -a, but omit implied . and ...It does not recurse into directories.
-lShow type/mode, link count, owner, group, size, time, and name.The displayed columns are not a stable machine-readable data format.
-hScale displayed sizes when paired with an option such as -l.It does not calculate the total content below a directory; use du.
-dList a directory entry rather than listing inside it.It does not mean “directories only.”
-t / -rSort by modification time / reverse the chosen order.Option meaning can interact; read the installed manual for the final ordering.
ls is a view for peopleNames can contain spaces, tabs, newlines, and control characters. Do not parse ls output to discover files in a script. Use a pathname-aware interface such as find, a shell glob/array, or a language filesystem API.

mkdir and touch: create structure deliberately

mkdir command-lab
mkdir -p command-lab/inbox/2026-08-14
mkdir -m 750 command-lab/private

touch command-lab/inbox/event.json
touch -c command-lab/inbox/must-already-exist.json
touch reference.log
touch -r reference.log copied-time.log
  • mkdir creates one directory; -p creates missing parents and does not complain when the requested directory already exists.
  • mkdir -m MODE requests the mode for the newly created final directory. Confirm the result with stat, especially when ACLs or platform policy apply.
  • touch updates access and modification times by default. If the path is missing it creates an empty file unless -c is used.
  • touch -r copies timestamps from a reference; it does not copy file content.

cp and mv: source first, destination second

cp -- source.json copy.json
cp -R -- fixtures fixtures-copy
cp -a -- validated-rules release-2026-08-14   # GNU archival copy

mv -- draft.json final.json                    # Rename in one directory.
mv -- final.json archive/                      # Move without renaming.
mv -i -- report.json archive/report.json       # Ask before overwrite.

cp leaves the source and creates or replaces the destination. mv changes the name or location and may replace an existing destination. A destination directory means “keep the source basename inside here”; a nonexistent final component becomes the new name. Use -i for an explicit overwrite prompt or -n to refuse overwriting where supported, but do not combine conflicting overwrite options and assume the result is portable.

Recursive is not the same as archivalcp -R traverses a directory tree. GNU cp -a also requests preservation of links and selected metadata. Neither is a transactional backup: interruption, special files, ACLs, extended attributes, sparse files, and cross-filesystem behavior need explicit verification.

rm and rmdir: inspect the exact target twice

ls -ld -- command-lab/empty
rmdir -- command-lab/empty          # Only succeeds when empty.

find command-lab/cache -maxdepth 2 -print
rm -I -r -- command-lab/cache       # GNU: one prompt before recursive removal.
test ! -e command-lab/cache && printf 'removed expected path\n'

rm removes directory entries directly; it normally does not use a desktop trash folder. -r descends through directories, -i prompts for each removal, and GNU -I gives one broader prompt. Avoid teaching yourself that -f is a default habit: it suppresses useful diagnostics and confirmations.

An alias is not a safety boundaryalias rm='rm -i' can help interactively, but scripts, other shells, absolute command paths, and overridden aliases can bypass it. Safety comes from an explicit target, a preview, narrow permissions, backups, and a command that remains understandable without an alias.

Verified against: the GNU Coreutils manuals for ls, mkdir, touch, cp, mv, and rm.

04 · Command walkthrough

find: start point, tests, then actions

Read a find command as a sentence: “Start here, keep entries that pass these tests, then take this action.” It walks below each start point unless depth is limited.

find logs -type f -name '*.json' -print
│    │     │       │              └─ action
│    │     │       └──────────────── name test; quoted for find to match
│    │     └──────────────────────── file-type test
│    └────────────────────────────── implicit AND between expressions
└─────────────────────────────────── start point
QuestionExpressionImportant detail
Exact shell-style name?-name '*.json'Quote the pattern so find, not the shell, evaluates it.
Name ignoring case?-iname '*.JSON'Widely available but not specified by POSIX; case folding is locale-sensitive.
Only files/directories/links?-type f, -type d, -type lThe default symbolic-link following policy affects which object is tested.
Limit traversal depth?-maxdepth 2, -mindepth 1GNU/BSD extensions; count the start point as depth 0.
Modified recently?-mmin -30Matches modification-age buckets less than 30 minutes; boundary rounding matters.
Modified after a known file?-newer baseline.timestampOften clearer than calculating a relative-day bucket.
Larger than 10 MiB?-size +10MUnits and rounding belong to the implementation; verify with its manual.

Build the expression one test at a time

# 1. Confirm the start point and traversal.
find logs -maxdepth 2 -print

# 2. Restrict the type.
find logs -maxdepth 2 -type f -print

# 3. Group OR conditions; implicit AND has higher precedence.
find logs -maxdepth 2 -type f \( -name '*.json' -o -name '*.log' \) -print

# 4. Add a time boundary that can be preserved as evidence.
touch -t 202608140900 baseline.timestamp
find logs -type f -newer baseline.timestamp -print

The escaped parentheses belong to find; escaping prevents the shell from treating them as shell syntax. Without grouping, an -o expression can apply differently than the English sentence in your head.

Actions: print first, execute second

# One invocation can receive many matched paths.
find logs -type f -name '*.json' -exec sha256sum -- {} +

# When a consumer needs a stream of arbitrary pathnames:
find logs -type f -print0 | xargs -0 sha256sum --

{} is replaced by matched pathnames and + batches as many as practical. A semicolon form, written \;, runs once per match. For arbitrary names, newline-separated find ... -print | xargs ... is unsafe because a pathname may contain whitespace or a newline; use -exec ... {} + or a NUL-delimited -print0/xargs -0 pair.

Do not begin with deletionRun the final tests with -print, review the complete target set, then change the action. -delete changes traversal behavior on GNU find and acts immediately; a misplaced operator or start point can remove far more than intended.

locate answers a different question

locate PATTERN searches a filename database, so it is usually much faster than walking the live tree. The database can be stale, omit paths, or include names that have disappeared. Use find when current filesystem state and metadata tests matter.

Verified against: the GNU Findutils manual, including traversal depth, expressions, actions, unusual filenames, and NUL-delimited output.

05 · Mental model

Names point to objects

PathA sequence of directory-entry names resolved from root or the current directory./var/log/app.log
→
Inode / file recordStores type, owner, permission mode, timestamps, size, and data-block references.ls -li
→
DataThe bytes read by a process. Several names may reference the same underlying object.sha256sum

Deleting a name removes a directory entry. The underlying object disappears only when no hard links and no open process references remain.

Common filesystem object types

TypeLeading mode characterDetection example
Regular file-Rule, log, report, executable, capture.
DirectorydRule bundle or case workspace.
Symbolic linklrules/current naming the active version.
SocketsLocal service or agent communication endpoint.
Deviceb / cDisk, terminal, or special kernel interface.
Named pipepProcess-to-process byte stream with a filesystem name.

06 · Navigation

Absolute, relative, and canonical paths

pwd -P

Print the physical current directory.-P resolves symbolic-link components where supported.

realpath <path>

Canonicalize a path.Resolves ., .., and links; availability and missing-path behavior vary by platform.

dirname /a/b/file

Return the directory portion.Useful for deriving a script-relative resource location.

basename /a/b/file

Return the final name.It manipulates pathname text; it does not inspect the object.

FormResolved fromExample
Absolute pathFilesystem root/var/log/auth.log
Relative pathProcess current working directoryreports/run.json
.Current directory entry./validate.sh
..Parent directory entry../fixtures
~Expanded by the shell~/.config/tool
Current directory belongs to the processA relative path that works in your terminal may fail under systemd, cron, CI, or a web service because that process starts elsewhere. Scripts should establish or derive their base directory deliberately.
# Resolve resources next to a Bash script, independent of caller cwd
script_dir=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd -P)
python3 "$script_dir/analyzer.py" "$script_dir/fixtures/access.log"

07 · Identity

Inodes, hard links, and symbolic links

PropertyHard linkSymbolic link
What it storesAnother directory entry for the same inodeA pathname string to resolve later
Across filesystemsNoYes
Can target directoriesNormally noYes
If original name is deletedContent remains through other hard linkLink may become dangling
Typical useMultiple names for one fileStable pointer to a versioned file/directory
 
printf 'rule: v1\n' > rule-v1.yml
ln rule-v1.yml rule-hard.yml
ln -s rule-v1.yml rule-current.yml

ls -li rule-v1.yml rule-hard.yml rule-current.yml
readlink rule-current.yml
stat rule-v1.yml

The two hard-linked names show the same inode number and link count. The symlink has its own inode and contains the target pathname.

Operational patternWrite and validate a new versioned rule bundle, then atomically replace a current symlink or rename the finished file into place. Readers see an old complete version or a new complete version—not a partial write.

08 · Access control

Read permission strings as policy

-rwxr-x---  1 analyst detection  842 validate.sh
│└┬┘└┬┘└┬┘
│ u  g  o
type  user / group / other
BitOn a regular fileOn a directory
r readRead file bytesList entry names
w writeModify file bytesCreate, delete, or rename entries, usually with execute
x executeExecute as a program when format/interpreter allowsTraverse/search through the directory

Symbolic and octal modes

chmod u+x validate.sh

Add one explicit permission.Symbolic mode is readable when making a narrow change.

chmod 640 report.json

Set the complete basic mode.6=rw for owner, 4=r for group, 0 for others.

chown analyst:detection file

Change owner and group.Requires appropriate privilege; do not use broad recursive ownership changes without resolving exact targets.

umask

Inspect default permission mask.It removes permissions from the creation mode requested by a program.

Mode bits are not the whole policyAccess can also be affected by parent-directory traversal, ACLs, extended attributes, SELinux/AppArmor policy, mount options, and platform-specific controls. Use namei -l on Linux or inspect every parent with ls -ld; use ls -le on macOS to expose ACLs.

Shebang plus execute bit

When you run ./validate.sh, the kernel checks execute permission and uses the shebang interpreter. When you run bash validate.sh, Bash only needs to read the file—the script's execute bit is not what starts it.

09 · Core working set

Inspect before changing

ls -la

List names and basic metadata.Use -i for inode numbers and -d to inspect a directory itself.

stat <path>

Inspect precise metadata.Output format differs between GNU/Linux and BSD/macOS.

file <path>

Classify content.Uses magic bytes and heuristics; an extension alone does not determine format.

find logs -type f -name '*.json' -print

Search by filesystem properties.Quote patterns so find, not the shell, evaluates them.

du -sh <path>

Measure referenced disk usage.Use for a capture or case directory.

df -h

Measure filesystem capacity.df -i checks inode exhaustion on filesystems that expose it.

sha256sum <file>

Hash content.On macOS, use shasum -a 256.

10 · On the job

Detection-engineering scenarios

MISSING LOGS

The collector reports “permission denied”

Inspect every pathname component and the identity of the collector process.

id collector_user
ls -ld /var /var/log /var/log/myapp
ls -l /var/log/myapp/events.json
# Linux:
namei -l /var/log/myapp/events.json

Look for: missing execute permission on a parent directory, wrong group membership, ACLs, or rotation creating new files with a different owner/mode.

RULE RELEASE

Switch rule bundles without partial reads

mkdir -p rules/releases/2026-08-13
cp validated/*.yml rules/releases/2026-08-13/
ln -sfn releases/2026-08-13 rules/current
readlink rules/current

Why it works: consumers open files through one stable name while the versioned directory remains immutable. Confirm your platform's symlink replacement behavior and rollback procedure.

DISK PRESSURE

A sensor stops writing although disk space looks available

df -h
df -i
du -sh /var/log/* 2>/dev/null
lsof +L1 2>/dev/null

Possible causes: inode exhaustion from many tiny files or a deleted log still held open by a process. Validate before rotating or restarting anything.

CASE DATA

An investigation report is world-readable

stat reports/private/finding.json
ls -ld reports reports/private
chmod 750 reports/private
chmod 640 reports/private/finding.json

Reasoning: restrict the directory and file to the actual collaboration group; avoid reflexively using 777, which converts an access problem into an integrity and confidentiality problem.

11 · Practice

Hands-on drills

1. Predict path resolution

15 min

Create fs-lab/a/b, enter b, and predict the canonical result of ., .., ../.., and ../../a/./b before running pwd -P or realpath.

  • Repeat after entering through a symlink.
  • Explain logical versus physical working-directory views.
  • State which base directory a relative path uses.

2. Prove link semantics

20 min
printf 'evidence\n' > original.txt
ln original.txt hard.txt
ln -s original.txt symbolic.txt
ls -li original.txt hard.txt symbolic.txt
printf 'changed\n' >> hard.txt
cat original.txt symbolic.txt
  • Identify shared versus distinct inode numbers.
  • Rename original.txt and explain both links afterward.
  • Explain link count and when content becomes reclaimable.

3. Execute-bit failure

15 min
printf '#!/usr/bin/env bash\necho validated\n' > validate.sh
chmod u+x validate.sh
./validate.sh
chmod u-x validate.sh
./validate.sh
failed_status=$?
printf 'direct-status=%s\n' "$failed_status"
bash validate.sh
interpreted_status=$?
printf 'interpreter-status=%s\n' "$interpreted_status"
chmod u+x validate.sh
  • Record the exact error after removing execute permission.
  • Explain why bash validate.sh still works.
  • Restore only the owner execute bit and verify the mode.
