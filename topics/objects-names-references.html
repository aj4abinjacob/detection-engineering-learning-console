01 · Purpose

Why names matter in detection work

Python code often handles one event as it passes from parser to enricher to rule. If two names designate one mutable object, an apparently local change can silently alter the event that later gets stored or alerted on.

TELEMETRY

Preserve raw evidence

Know when an enrichment field changed the same dictionary that represents the raw event.

CORRECTNESS

Compare the right property

Use equality for values and identity only when the same instance is the question.

RELIABILITY

Understand function calls

A function receives another name for an object, so mutation is visible to its caller.

INTERVIEWS

Explain the mechanism

“Pass by object reference” is imprecise; assignment and arguments bind names to objects.

02 · Mental model

Names are labels; objects carry state

Think “two labels on one evidence box.” Mutating the box is observable through either label. Rebinding one label points only that label elsewhere.

event = {"ip": "203.0.113.8", "tags": []}
queued = event                 # binds queued to the same dict
queued["tags"].append("vpn")    # mutates that shared dict
event = {"ip": "198.51.100.4"} # rebinds event; queued is unchanged

print(queued)  # {'ip': '203.0.113.8', 'tags': ['vpn']}

Use: run this when explaining an aliasing surprise. Assumption: the dict is mutable. Risk: treating the first assignment as a copy causes accidental mutation of audit or queue data.

03 · Assignment and calls

Assignment, parameters, and returns all bind names

For a = b, Python evaluates the expression on the right, then binds a to that object. A function call does the same binding for its parameter. A return value is likewise bound by the caller. This is often called “call by sharing.” It is neither copying nor C++-style pass-by-reference.

def normalize(record: dict[str, object]) -> None:
    record["source"] = "gateway"  # mutates caller's dict

raw = {"status": 401}
normalize(raw)
print(raw)  # {'status': 401, 'source': 'gateway'}

def redacted(record: dict[str, object]) -> dict[str, object]:
    return {**record, "token": "[redacted]"}  # new outer dict

safe_for_log = redacted({"token": "secret", "status": 401})
Copy depth is a policy choiceThe spread expression creates a new outer dictionary but preserves references to nested objects. Topic 2.2 covers shallow and deep copies. For sensitive evidence, define which fields may be changed and retain an immutable/raw representation when provenance matters.

Integers can look like copying

count += 1 computes a new integer and rebinds count, because integers are immutable. The analogous list operation, items += [x], normally mutates the existing list in place. The operator spelling is not the rule; the type's operation is.

05 · Runtime details

id(), reference counts, and garbage collection

id(x) is an integer guaranteed unique and constant only while x exists. In CPython it is usually the memory address, but that is an implementation detail—not a portable address or a durable event identifier. Once an object is gone, a later object may reuse the integer.

record = {"request_id": "r-17"}
alias = record
print(id(record) == id(alias))  # True: useful within this live process

# Persist record["request_id"], not id(record), in a report or correlation key.

CPython commonly uses reference counting: when its reference count reaches zero, it can finalize an object promptly. It also has a cyclic garbage collector for unreachable cycles such as two objects referring to each other. Other Python implementations may use a tracing garbage collector, a JIT, or different timing. Never make correctness, cleanup, locking, or security logic depend on immediate destruction.

Do not teach cache behavior as language semanticsSome CPython builds may reuse small integers or intern some strings. That can make "x" is "x" or 256 is 256 appear true. It is not a language promise and can vary with construction, version, optimization, and implementation. Compare values with ==.

06 · Investigation workflow

Inspect aliasing without turning it into production logic

id(obj)

Inspect live identity while debugging.Use in a local reproduction to show aliases. It assumes both references are live; never serialize it as a stable identifier.

obj is None

Test a singleton sentinel.Use for an absent optional value. It assumes the API uses None for absence; do not replace a valid empty string or zero with a truthiness test.

new = {**old}

Create a shallow outer-dict copy.Use before adding a top-level enrichment. Nested lists/dicts remain shared, so it is unsafe if nested evidence will change.

python3 -X dev reproduce.py

Run a local reproduction with extra runtime checks.Useful during development on supported CPython versions; it can be slower and is not a production switch or portability guarantee.

07 · On the job

Detection-engineering scenarios

ENRICHMENT

A “raw” event acquires an analyst tag

A parser stores raw, then an enricher receives the same dict and appends to its nested labels list. The evidence store now shows a field that did not arrive on the wire. Decide whether enrichment is intended in-place; otherwise construct a separate normalized event and keep provenance explicit.

DEDUP

Two events with the same content are not the same delivery

A retry generates a new dict equal to the first one. is says false, correctly; identity cannot deduplicate across queues or processes. Use a documented value key such as producer event ID and a time window.

SENTINEL

An absent geo lookup differs from an empty result

Use None to represent “lookup not performed/unknown” and test it with is None. An empty mapping can mean “lookup succeeded but has no fields.” Collapsing both with if not geo destroys observability.

MEMORY

A long-lived worker appears to retain events

Investigate references with a bounded local reproduction and profiler tools; do not assume CPython reference-count timing establishes a leak. A global cache, closure, queue, or exception traceback can keep a name reachable; a cycle alone is not automatically a production leak.

Hands-on drills

1. Prove shared-list aliasing

15 min
events = [{"ip": "203.0.113.9", "tags": []}]
queue = events
queue[0]["tags"].append("watch")
print(id(events), id(queue), events)

2. Build an identity/equality test matrix

20 min
a = {"status": 401}; b = {"status": 401}; c = a
for label, left, right in [("equal-distinct", a, b), ("alias", a, c)]:
    print(label, "is:", left is right, "==:", left == right)
  • Save the output and a one-sentence meaning for each row.
  • Add a None example using is None.
  • State one case where persisting id() would be wrong.

3. Preserve raw and normalized telemetry

25 min
raw = {"ip": "203.0.113.9", "headers": {"user-agent": "Lab"}}
normalized = {**raw, "source": "edge"}
normalized["headers"] = {**raw["headers"], "user-agent": "lab"}
print(raw)
print(normalized)
  • Save both JSON-like outputs as an artifact.
  • Prove that raw headers were not changed.
  • Identify which two copies are shallow and why the explicit nested copy matters.
