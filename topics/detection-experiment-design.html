Purpose

Why this matters in detection engineering

A detection experiment begins with a falsifiable hypothesis, declared unit and population, independent and dependent variables, controls, assignment or sampling method, analysis plan, stopping rule, and limitations. Pre-registration prevents results from silently rewriting the original question.

A detection engineer must be able to trace how an observation becomes a feature, how that feature supports an inference, and how policy turns the inference into an action. The useful unit for this topic is a time-stamped preregistration plus immutable fixtures, environment manifest, code and data hashes, result table, deviations, negative results, and reproduction steps. Preserve enough lineage to reproduce it without collecting content that the decision does not require.

Boundaries

What can go wrong

Closest legitimate lookalike: noise, seasonality, learning effects, generator artifacts, and system load can create a difference without the proposed mechanism.

Pipeline or interpretation failure: changing thresholds after seeing results, optional stopping, multiple unreported hypotheses, no negative control, and test-set reuse turn exploration into confirmation.

Safety boundary: work only with supplied sanitized fixtures or systems and accounts you own and are authorized to test. Minimize identifiers, exclude secrets and content, bound retention and access, and provide an accessible path when an automated action could affect a person.

Do not overclaimThis guide establishes a method for controlled defensive evidence. It does not prove identity, intent, causality, universal tool behavior, or how a third-party system will classify traffic.

Method

A repeatable defensive workflow

  1. Declare the question and scope. Name the owned route, entity, time range, authorization, expected population, and prohibited data before collection.
  2. Version the evidence. Save a time-stamped preregistration plus immutable fixtures, environment manifest, code and data hashes, result table, deviations, negative results, and reproduction steps, its schema or tool version, observation point, event and availability times, and missing-value behavior.
  3. Build a negative control. Include noise, seasonality, learning effects, generator artifacts, and system load can create a difference without the proposed mechanism and state the response it should receive.
  4. Replay and decide. Recompute from immutable input, compare expected output, inspect false positives and false negatives, then apply separate exploratory from confirmatory analysis, record deviations, report uncertainty and null results, and invite reproduction from sanitized artifacts.

Practice

Detection-engineering scenarios

BASELINE

1. The observed distribution changes

Trigger: a monitor for Falsifiable hypotheses; controls; pre-registration; reproducibility shifts outside its recorded baseline. Artifact: a time-stamped preregistration plus immutable fixtures, environment manifest, code and data hashes, result table, deviations, negative results, and reproduction steps. Reasoning: compare time, producer, release, population, and data quality before attributing the shift to abuse. Boundary: a changed distribution is an observed fact, not a malicious label.

LOOKALIKE

2. A legitimate journey matches the candidate

Trigger: the candidate logic fires on noise, seasonality, learning effects, generator artifacts, and system load can create a difference without the proposed mechanism. Artifact: a labeled negative-control replay. Reasoning: preserve the case, inspect which feature dominated, and choose a proportionate fallback. Boundary: do not tune the case away without measuring what new false negatives the change creates.

QUALITY

3. The pipeline changes while the rule stays green

Trigger: changing thresholds after seeing results, optional stopping, multiple unreported hypotheses, no negative control, and test-set reuse turn exploration into confirmation. Artifact: contract-test result, schema versions, and quality counters. Reasoning: quarantine or mark degraded evidence and restore the producer contract before judging detection quality. Boundary: absence, default values, and parser failures are not benign observations.

POLICY

4. Evidence is strong enough to review, not to punish

Trigger: several versioned signals agree on an unusual owned-lab journey. Artifact: feature lineage, reason codes, policy version, and expected guardrails. Reasoning: separate exploratory from confirmatory analysis, record deviations, report uncertainty and null results, and invite reproduction from sanitized artifacts. Boundary: preserve rollback and never infer that an offline score proves the causal benefit of an intervention.
