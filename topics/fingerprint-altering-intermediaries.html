Practical field guide · Observation topology

Ask which peer produced the fingerprint.

A proxy, CDN, load balancer, or TLS terminator can end one connection and create another. The origin often fingerprints the intermediary—not the browser that began the journey.

01 · Purpose

Connections do not pass through a terminator unchanged

Intermediaries may terminate TLS, decode/re-encode HTTP, pool connections, normalize headers, change TCP peer, and add forwarding metadata. Evidence must identify its hop and owner.

New handshake

Origin sees proxy’s ClientHello when proxy re-originates TLS.

Proxy → originproxy TLS/HTTP/TCP features at origin.

End-to-end facts such as application request ID can be deliberately propagated, but transport fingerprints generally belong to the hop that generated them.

03 · TLS effects

A TLS terminator observes client→proxy ClientHello/JA4 at the edge. If it opens TLS to origin, it emits its own ClientHello/JA4, cipher negotiation, ALPN, and server-facing behavior. TLS passthrough is different: origin may observe the original TLS peer but still has network/load-balancer effects. Verify architecture; “behind CDN” does not uniquely determine termination.

04 · HTTP effects

A proxy can translate HTTP/2 client traffic to HTTP/1.1 upstream, re-encode HTTP/2, normalize/reorder fields, add/remove hop-by-hop fields, buffer bodies, and reuse upstream connections. Thus origin header order, HTTP/2 SETTINGS, and connection concurrency may characterize proxy configuration. Application semantics should survive only according to explicit forwarding/policy rules.

05 · TCP effects

TCP-level features at origin—MSS, window, options, TTL-like observations—describe the direct TCP peer/proxy path, not necessarily user device. NAT/CDN/load balancing can further alter address/path evidence. Record sensor position and peer IP role before interpreting TCP fingerprints.

06 · Forwarded client context

Forwarded headers can carry original address/proto/host only through a trusted configured chain. The proxy must strip client-supplied forwarding headers and set/append trusted values; origin must trust them only from allowlisted proxy peers. They can convey application context, not recreate client TLS/TCP fingerprint.

07 · Learner-owned direct/proxy comparison

direct:  local client → local terminator/origin
proxied: local client → local proxy/terminator → local origin
record: point, peer role, TLS version/ALPN, HTTP version, route outcome
# Compare sanitized artifacts; do not treat proxy simulation as a CDN test.

Use: a localhost/owned lab with synthetic requests and hard caps. Risk: a local proxy may not behave like a commercial CDN; document exact software/configuration and avoid extrapolating to third parties.

08 · What an intermediary cannot prove

It cannot turn a proxy→origin TLS fingerprint into proof of browser identity. It cannot make an untrusted X-Forwarded-For trustworthy. It cannot guarantee a request’s human intent. It may preserve a deliberate application request ID, authenticated principal context, and validated client IP according to policy; these remain separate, auditable claims.

09 · Safety

Compare only systems you ownUse a local proxy/terminator and learner-owned capture/artifacts. Do not probe CDNs, connect to vendor endpoints, capture shared traffic, or use intermediary knowledge to alter/evasion-test fingerprints.

10 · Defensive scenarios

ORIGIN

All origin JA4 values match

Trigger: uniform TLS output. Artifact: topology/config. Observation: proxy-to-origin TLS. Reasoning: origin sees proxy. Boundary: no browser attribution.

H2

HTTP/2 profile disappears upstream

Trigger: edge H2, origin H1. Artifact: local direct/proxy table. Observation: protocol translation. Reasoning: intermediary reserialization. Boundary: not client anomaly.

IP

Origin trusts direct XFF

Trigger: client header accepted. Artifact: proxy trust diagram. Observation: spoofable chain. Reasoning: config defect. Boundary: fix trust policy, not reputation label.

TCP

OS signal contradicts user agent

Trigger: mismatch. Artifact: sensor peer role. Observation: proxy stack. Reasoning: topology alternative. Boundary: no proxy/malice proof.
