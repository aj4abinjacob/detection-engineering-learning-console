01 · Purpose

Logs are evidence for the next investigator

A command’s stdout is for its immediate user; a log record is durable operational evidence. Good records explain what happened, where it happened, and which run/configuration produced it—while keeping secrets and untrusted text out of unsafe sinks.

TRIAGE

Levels express urgency

A 5xx parse failure, expected retry, and developer trace should not have identical operational weight.

CORRELATION

Fields make joins possible

Run ID, rule version, input ID, and outcome support a timeline without prose parsing.

REPRODUCTION

Provenance explains behavior

Record which configuration source won, not sensitive configuration values.

BOUNDARY

Logs are data exfiltration paths

Any field can reach a shared console, vendor, ticket, or retention system.

02 · Mental model

A named logger creates records; handlers decide delivery

→
LogRecordLevel, message, time, and safe fields.logger.info(...)
→

Logger names are dotted. A child normally propagates records to ancestors; duplicate output often means both child and root have handlers or propagation was misunderstood.

03 · Mechanics

Use levels, handlers, and formatters deliberately

import logging

logger = logging.getLogger("analyzer.parse")

def parse_one(line: str, line_number: int) -> None:
    logger.debug("parse_started line=%d", line_number)
    if not line:
        logger.warning("empty_record line=%d", line_number)
        return
    logger.info("parse_completed line=%d", line_number)
logging.getLogger(__name__)

Obtain a module-named logger.Use it in library/application modules so hierarchy is meaningful. Do not configure global handlers at import time; the application entry point owns delivery policy.

logger.debug("value=%s", value)

Log with deferred formatting.Use parameterized logging so formatting occurs only if enabled. It does not sanitize value; redact/validate sensitive or untrusted values before logging.

logging.basicConfig(...)

Make a small application’s initial root setup.Use once at an entry point. It is not a dependable per-library configuration API and may do nothing if handlers already exist.

Typical intent: DEBUG diagnostic detail, INFO normal milestones, WARNING unexpected but continuing behavior, ERROR failed operation, CRITICAL service-threatening failure. Levels are routing/severity conventions; they are not incident classifications by themselves.

04 · Queryable records

Prefer stable fields over ad-hoc prose

import json, logging, uuid

run_id = str(uuid.uuid4())

def log_event(logger: logging.Logger, event: str, **fields: object) -> None:
    record = {"event": event, "run_id": run_id, **fields}
    logger.info("%s", json.dumps(record, separators=(",", ":"), sort_keys=True))

log_event(logger, "rule_evaluated", rule_id="auth-failure-v1", outcome="no_match")

This small JSON-message pattern is suitable for a lab; a production system may use a vetted JSON formatter and schema. Keep field names stable, timestamps in the formatter or record, and a documented schema version. A per-run UUID is correlation metadata, not an authentication secret. Do not use an account email, raw IP, or request body as a convenient run ID.

05 · Data handling

Logging can leak and can be manipulated

import hashlib

def safe_subject(value: str) -> str:
    # Pseudonym is still sensitive correlation data; apply retention policy.
    return hashlib.sha256(value.encode("utf-8")).hexdigest()[:12]

def single_line(value: str) -> str:
    return value.replace("\r", "\\r").replace("\n", "\\n")

Never log passwords, API keys, session cookies, authorization headers, raw payment data, or full request bodies. Treat identifiers, IPs, user agents, and hashes according to your privacy and retention policy. Escape or structure untrusted strings to prevent forged multi-line records (log injection); even escaped data may be unsafe to retain.

06 · Precedence

Merge sources in one order: default < file < env < flag

from dataclasses import dataclass, replace

@dataclass(frozen=True)
class Settings:
    threshold: int = 20
    log_level: str = "INFO"
    threshold_source: str = "default"

def apply_threshold(settings: Settings, raw: str | None, source: str) -> Settings:
    if raw is None:
        return settings
    value = int(raw)
    if value < 1 or value > 10_000:
        raise ValueError("threshold must be 1..10000")
    return replace(settings, threshold=value, threshold_source=source)

# Build in this exact order: defaults, approved file, environment, CLI flag.

Do not let scattered modules read environment variables independently: precedence becomes invisible and tests become order-dependent. Parse untrusted strings once at the boundary into typed settings, validate ranges/enums, and keep a source label for each effective setting. File location and environment naming are deployment-specific; document them rather than guessing.

07 · Explain effective settings

Provenance beats “it used the environment somehow”

def describe(settings: Settings) -> dict[str, object]:
    return {
        "threshold": settings.threshold,
        "threshold_source": settings.threshold_source,
        "log_level": settings.log_level,
    }

# Safe CLI output: do not include secrets or raw environment values.

For each setting, preserve the winning source and a safe effective value where policy allows. Validate configuration files as data—not imported Python—and restrict their permissions if they can contain credentials. Resolve configuration during application startup, then pass an immutable settings object to the core rather than rereading environment state halfway through an event stream.

08 · Failure modes

Common operational mistakes

SymptomCauseResponse
Duplicate recordsHandlers at child and root plus propagation.Choose one ownership point; inspect handler chain before setting propagate=False.
No debug outputLogger/handler effective level filters it.Inspect both levels and deployment configuration, not only the log call.
Tests fight setupImport-time basicConfig or environment reads.Configure at main; inject settings/loggers or use pytest capture fixtures.
Bad config starts serviceStrings coerced late or invalid values silently default.Fail startup with a clear non-secret message and nonzero exit.
PII/secret in logRaw context interpolated for debugging.Redact, rotate/restrict access under policy, and add a regression test.

Platform/version note: examples use Python 3.11+ standard logging. Container, systemd, Windows Event Log, and cloud collectors impose their own formatting, timestamp, rotation, and retention behaviors; test the configured deployment sink. File handlers need deliberate permissions and rotation—avoid assuming a local disk is durable or private.

09 · On the job

Detection-engineering scenarios

DEPLOY

Threshold changes after rollout

Emit one startup record with threshold, source, rule version, and run ID—not raw environment variables. It lets an investigator distinguish a behavior change from an event-volume change.

PRIVACY

Failed login parser needs context

Log a safe failure category, line/record ID, and bounded field names. Do not include the submitted password, authorization header, or raw payload to make the issue convenient.

PIPELINE

Collector creates duplicate events

Find duplicate handler propagation before deduplicating downstream. A logger configuration defect and a source duplication defect look similar in a dashboard but require different corrections.

INCIDENT

Operator needs a temporary trace

Use a bounded, authorized DEBUG window and remove it through configuration after collection. Preserve the rule/run ID and sanitization rules so the trace does not become a new long-lived sensitive dataset.

10 · Practice

Hands-on drills

1. Replace prints with records

35 min

Save artifacts/logging/analyzer.py and run.log. Emit DEBUG, INFO, WARNING, and ERROR from a synthetic analyzer run with a run ID.

  • Identify logger, handler, formatter, and effective level.
  • Show one safe structured record.
  • Prove DEBUG is filtered or emitted by changing configuration, not code.

2. Demonstrate precedence

30 min

Save settings.py, a non-secret settings.json, and precedence-transcript.txt showing default, file, environment, and flag wins.

  • Validate an out-of-range threshold and show failure.
  • Record the winning source.
  • Do not save real environment secrets in the artifact.

3. Redaction and injection test

25 min

Save safe_logging_test.py and safety-output.txt. Feed synthetic newline-bearing input and a fake token through your logging boundary.

  • Show that the token never appears.
  • Show that newlines cannot forge a second record.
  • Describe where retention/access controls live outside code.
