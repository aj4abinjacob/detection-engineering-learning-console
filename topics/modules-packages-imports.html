01 · Purpose

Why imports are a production boundary

A detection job launched by a scheduler, container, CI runner, or another engineer has a different working directory and installed environment from your terminal. Import paths make that difference either explicit or a latent outage.

REPRODUCIBILITY

One installed artifact

Code executes by package name, not by an accident of where the shell started.

SECURITY

Resolution order is trust

An untrusted current directory can shadow an expected module.

MAINTENANCE

Layers break cycles

Import cycles reveal two modules that know too much about each other.

OPERATIONS

CLI is a contract

An entry point gives automation a stable executable and exit behavior.

02 · Mental model

An import finds, creates, executes, then caches a module

Import requestimport abuseguard.parser names a module.
search →
Finder / pathFinders consult package paths and sys.path in order.
execute →
Module cacheExecuted module object is normally cached in sys.modules.

Top-level module code runs on first import in that interpreter. Keep it small: definitions and constants are fine; network calls, configuration mutation, and process startup create fragile import side effects.

03 · Resolution and trust

sys.path ordering decides what code is imported

import sys
for index, entry in enumerate(sys.path):
    print(index, repr(entry))

import abuseguard
print(abuseguard.__file__)

Use: diagnose a surprising import in a disposable environment. Assumption: __file__ exists for this module; some frozen/built-in modules differ. Risk: do not “fix” production by blindly appending paths—ordering can load stale or attacker-controlled code.

For script execution, the script directory commonly appears early; environment configuration, site-packages, virtual environments, and installation layout then contribute entries. Exact ordering varies by Python invocation, virtual environment, platform, and flags. The current working directory is therefore not a dependency-management mechanism.

Import shadowing is a real riskDo not name a project file json.py, email.py, typing.py, or the same name as a dependency. A directory containing an unreviewed requests.py can cause a trusted program launched there to import the wrong code. Use isolated environments, package installs, and inspect module.__file__ during diagnosis.

04 · Import forms

Use absolute imports for package boundaries

# src/abuseguard/cli.py
from abuseguard.analysis import summarize  # absolute: clear from every package module

# src/abuseguard/analysis.py
from .models import AccessEvent            # explicit relative: local package relationship

# Run installed module/entry point, not this file by pathname:
python3 -m abuseguard.cli --help

Absolute imports name the installed package and remain clear during refactors. Explicit relative imports are useful inside a package but require package context; executing python src/abuseguard/cli.py makes __package__ unavailable and can fail with “attempted relative import.” Run python -m package.module during development or install the command.

Imports bind module attributesfrom module import name copies a binding into the importing module at import time; it is not a live alias for later reassignment. Prefer import module when a qualified name improves provenance or avoids a collision.

05 · Architecture signal

Circular imports expose partially initialized modules

# Bad shape: parser.py imports report.py, while report.py imports parser.py.
# Typical failure: ImportError: cannot import name ... from partially initialized module ...

# Better shape:
# models.py  ← parser.py  ← service.py  → report.py
#                 all depend on models; models depends on neither.

Python places a module in its cache before executing its body to support recursion. If module A imports B while A is unfinished and B asks for an attribute A has not defined yet, the requested attribute is absent. Do not solve the architecture with scattered function-local imports unless laziness is the actual, documented dependency boundary.

  1. Read the traceback from the first project module.Record the import chain, not only the final missing name.
  2. Move shared types/protocols downward.Create a dependency-light models or interfaces module.
  3. Invert the dependency.Pass a reporter/callback into the service rather than importing the service from the reporter.
  4. Retest in a clean interpreter.Cached modules can hide import-order differences in an interactive shell.

06 · Package the analyzer

Declare what is installed

abuseguard/
├── pyproject.toml
├── src/
│   └── abuseguard/
│       ├── __init__.py
│       ├── cli.py
│       ├── analysis.py
│       └── models.py
└── tests/

# pyproject.toml (tool-specific build configuration omitted here)
[project]
name = "abuseguard"
version = "0.1.0"
requires-python = ">=3.11"
[project.scripts]
abuseguard = "abuseguard.cli:main"

Use: the modern pyproject.toml project metadata format with a build backend such as setuptools, Hatchling, or another documented backend. Assumption: your chosen backend supports the shown project layout and script declaration. Risk: backend configuration is not universal; consult its current documentation rather than copying an incompatible table.

python3 -m venv .venv
. .venv/bin/activate       # POSIX shells; Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e .
abuseguard --help
python -c 'import abuseguard; print(abuseguard.__file__)'

Use: editable install while actively developing a local project. Assumption: the virtual environment is active and the project/build backend supports editable installs. Risk: editable install links/imports your source rather than producing a deployment artifact; test a regular wheel install in a clean environment before release. Activation is convenience, not a security boundary.

07 · Entry points

Keep importable code separate from process startup

# src/abuseguard/cli.py
import argparse
from abuseguard.analysis import summarize_file

def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(prog="abuseguard")
    parser.add_argument("path")
    args = parser.parse_args(argv)
    print(summarize_file(args.path))
    return 0

if __name__ == "__main__":
    raise SystemExit(main())

Use: expose a zero-argument entry-point callable and return an integer status. Assumption: user-facing failures are converted to documented diagnostics in main (Topic 3.2). Risk: importing cli must not parse process arguments or exit; tests and other programs need to import it safely.

08 · Failure and safety

Diagnose without path hacks

python3 -c 'import pkg; print(pkg.__file__)'

Locate an imported package.Use for a local import mismatch. It assumes the import is safe to execute; avoid importing untrusted code merely to inspect it.

python3 -m package.module

Run with package context.Use for module development. It assumes the package is discoverable through the installed environment or an intentional development path.

python -m pip show package

Inspect installed distribution metadata.Use to distinguish distribution version/location from import name. Names can differ; do not infer trust from a display name.

Platform and version noteShell activation command, launcher name (python vs python3 vs Windows py), path separators, and packaging backend behavior vary. Pin a supported Python range in project metadata and run CI against the versions you claim—not just the interpreter on your laptop.

09 · On the job

Detection-engineering scenarios

SCHEDULER

The nightly analyzer works locally but fails in cron

It depended on the current directory or a shell-set PYTHONPATH. Install the package in the job environment and invoke its entry point with absolute input/config paths; log the package version and command context without secrets.

INCIDENT

A library imports a local file instead of the expected dependency

Use module.__file__ in a controlled diagnostic session, remove/rename the shadowing project file, and rebuild the environment. Avoid adding arbitrary directories to sys.path, which broadens the executable trust boundary.

REFACTOR

A new reporter creates a circular import

Trace the chain, put shared event types in a low-level module, and inject the reporting dependency. The fix should reduce coupling, not merely defer the import until runtime.

RELEASE

Editable development hides missing package data

The source tree makes a template or rule file appear available. Build a wheel, install it into a fresh virtual environment, and run the entry point from another directory before shipping.
