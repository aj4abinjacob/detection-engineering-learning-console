TLS deeply

Parse ClientHello by length and order, not guesses.

ClientHello is normally observable before encryption and offers ordered suites/extensions. It is low-confidence metadata, not identity.

Why it matters

ClientHello structure supports troubleshooting and cautious client clustering. Implementation, OS, policy, middleboxes, GREASE, collisions, and mimicry prevent identity/malicious verdicts.

Structure and vectors

legacy_version; random; legacy_session_id; cipher_suites; compression_methods; ordered extensions(type,length,data)

It is a handshake message in a record. Each vector has declared length; parser validates offset plus length before reading and keeps offset/type/reason on failure.

Version semantics

TLS 1.3 ClientHello legacy_version is 0x0303 for compatibility. Actual offered versions are supported_versions extension. Do not call 0x0303 alone a TLS 1.2 client; selection occurs in ServerHello.

Cipher suites

Client offers ordered suites. TLS 1.3 suites describe AEAD/hash while key exchange/signature selection lives in extensions. Order can vary normally and does not prove chosen suite.

Extension order

Preserve ordered server_name, supported_versions, signature_algorithms, supported_groups, key_share, ALPN, and unknown extensions. A set loses forensic/fingerprint context. Safely skip unknown bounded data; unknown is not hostile.

Groups, signatures, ALPN

supported_groups offers groups; key_share contains shares; signature_algorithms offers schemes; ALPN offers application protocols; SNI offers intended name conventionally. Each is an offer, not proof of selected/used behavior.

GREASE

GREASE intentionally tests extensibility and is normally expected. Keep raw values and normalization decision distinct. Fingerprint schemes commonly exclude GREASE under their specification.

Offline bounded parser

This minimal hello_dissect.py parses a raw ClientHello body, not its 4-byte handshake header or TLS record header. It deliberately keeps unknown extensions and rejects trailing, truncated, duplicate, odd-length, and oversized input:

MAX_HELLO = 65536

def take(buf, pos, size):
    if size < 0 or pos < 0 or pos + size > len(buf):
        raise ValueError(f"truncated at {pos}, need {size}")
    return buf[pos:pos + size], pos + size

def vector(buf, pos, width):
    raw, pos = take(buf, pos, width)
    size = int.from_bytes(raw, "big")
    return take(buf, pos, size)

def dissect(body):
    if len(body) > MAX_HELLO:
        raise ValueError("ClientHello exceeds parser policy")
    version, pos = take(body, 0, 2)
    random, pos = take(body, pos, 32)
    session_id, pos = vector(body, pos, 1)
    suites, pos = vector(body, pos, 2)
    if len(suites) % 2:
        raise ValueError("odd cipher-suite vector")
    compression, pos = vector(body, pos, 1)
    extensions, pos = vector(body, pos, 2)
    if pos != len(body):
        raise ValueError("trailing ClientHello bytes")

    ordered, seen, ext_pos = [], set(), 0
    while ext_pos < len(extensions):
        raw_type, ext_pos = take(extensions, ext_pos, 2)
        ext_type = int.from_bytes(raw_type, "big")
        payload, ext_pos = vector(extensions, ext_pos, 2)
        if ext_type in seen:
            raise ValueError(f"duplicate extension {ext_type}")
        seen.add(ext_type)
        ordered.append((ext_type, payload))
    return {
        "legacy_version": version.hex(),
        "cipher_suites": [int.from_bytes(suites[i:i+2], "big")
                          for i in range(0, len(suites), 2)],
        "extensions": ordered,
    }

Extend this with equally bounded decoders for supported_versions, supported_groups, signature_algorithms, key_share, and ALPN. Every nested vector has its own length prefix; never trust an inner length just because the outer vector fit. Parsing does not decrypt TLS or authorize capture.

ECH changes what the parser sees

RFC 9849 ECH leaves a syntactically valid ClientHelloOuter visible while encrypting a ClientHelloInner. A network sensor parses and fingerprints the outer values, which can intentionally differ from the private SNI, ALPN, and other inner values. An endpoint parser may have authorized access to the inner hello. Store the observation point and ECH acceptance/fallback state with any derived feature.

Safety and limits

No live capture/external endpoint is needed. Do not retain private traffic, SNI, cookies, or secrets. Browser version, resumption, ECH, proxy, and policy change output; same client can vary and different clients can collide.

Detection scenarios

Wrong TLS version label

A network parser emits tls.version=1.2 for a new browser because it copied legacy_version=0x0303. Inspect the raw ClientHello at the passive sensor, decode the ordered supported_versions vector, and compare the ServerHello selection. Correct the field contract; the compatibility value alone is not evidence that TLS 1.2 was offered or selected.

ALPN drift

A client cluster that usually offers h2,http/1.1 begins offering only http/1.1. Compare capture point, raw ALPN bytes/order, destination, browser release, policy, and whether an enterprise proxy originated a new hello. Treat it as configuration or path drift until request behavior and endpoint evidence corroborate abuse.

Unknown extension

The parser's unknown-extension counter spikes after a client rollout. Preserve extension type, declared length, order, sensor/parser version, and a sanitized bounded payload digest; verify the vector consumed exactly its declared bytes. A standards experiment or GREASE-like behavior is a legitimate explanation, so “unknown” drives parser review rather than a malicious verdict.

Fingerprint drift

The same synthetic client label produces two fingerprints on consecutive days. Diff raw cipher/extension order, GREASE removal, ECH outer/fallback state, resumption, tool version, and path through the terminator. Only after separating collector/normalizer changes from real hello changes should the team decide whether to split a cluster or tune a rule.
