01 · Purpose

Ranking is a data-retention decision

A top-N report can mean “all distinct entities were counted exactly, then select N” or “keep N individual values while streaming.” Those are different questions with different memory needs.

TRIAGE

Rank noisiest entities

Counts need a stable entity key and interval definition.

SCALE

Avoid needless sort

A small N does not require ordering every result.

REPRODUCIBILITY

Resolve ties

Stable output needs an explicit secondary order.

TRUST

State approximation

Bounded-memory approximate heavy hitters are not exact counts.

03 · Full sort

def top_sort(counts: dict[str, int], k: int):
    return sorted(counts.items(), key=lambda item: (-item[1], item[0]))[:k]

Use: you need all entities ordered, e fits memory, or simplicity dominates. Cost: O(e log e) time and output/list allocation proportional to e. Risk: omitting the secondary key lets equal-count presentation depend on input/insertion order; that might be deterministic for one source but not a documented report contract.

04 · Counter and selection helpers

from collections import Counter
import heapq

counts = Counter(["a", "b", "a", "c"])
top_counter = counts.most_common(2)
top_heap = heapq.nlargest(2, counts.items(), key=lambda item: item[1])

Use: Counter.most_common for idiomatic frequency ranking, heapq.nlargest for generic selection when k is small relative to e. Assumption: all counts fit in memory. Risk: tied ordering is not a universal semantic guarantee to rely on; if a report/test needs deterministic ties, use a compound ordering/key and test it. Check current Python docs for implementation-specific performance details rather than treating a helper name as a complexity promise.

05 · Streaming bounded heap

import heapq

def top_values(values, k: int):
    if k < 0:
        raise ValueError("k must be nonnegative")
    if k == 0:
        return []
    heap = []  # (score, stable_tie, value), at most k entries
    for score, tie, value in values:
        item = (score, tie, value)
        if len(heap) < k: heapq.heappush(heap, item)
        elif item > heap[0]: heapq.heapreplace(heap, item)
    return sorted(heap, reverse=True)

Use: one-pass top individual values where k is bounded and score/tie are comparable. The contract returns an empty list for zero and rejects negative k; test both boundaries. Cost: O(n log k) time, O(k) heap state. Risk: this does not calculate top IPs by frequency; a repeated IP must first be counted (O(e) exact state) or summarized upstream/approximately. Avoid heap tuples whose later fields are incomparable, such as arbitrary dicts, when scores tie.

06 · Exactness and ties

Make ranking policy reviewable

QuestionDeclare
What is scored?Count, bytes, error rate, or individual event score.
What interval?Event-time/processing-time start/end and timezone.
How do ties sort?Canonical entity text ascending, first-seen sequence, or another deterministic rule.
Exact or approximate?Exact count map, upstream aggregate, or named approximate sketch.
What if fewer than k?Return available results, never invent rows.
Correctness includes reproducibilityPython dict insertion order is a language guarantee in current supported Python versions, but an upstream stream’s order can vary. Make the secondary ranking field explicit when output is compared, audited, or used by automation.

07 · The 10 GB question

Choose from constraints, not file size alone

For a 10 GB log, stream records; never load the whole file merely to rank. If exact per-IP top-N is required and distinct IP cardinality fits the memory budget, maintain a Counter while streaming then select with a heap/sort. If e does not fit, use external aggregation/sort, a database/stream processor, or a clearly labeled approximate heavy-hitter algorithm with error bounds. A raw bounded heap cannot answer exact frequency top-N without counts.

Input assumptionsSpecify parse format, trusted client-identity field, time interval, expected e, memory limit, and whether results must be exact. A 10 GB file may have few or millions of distinct entities; bytes alone do not choose the algorithm.

08 · Benchmark all three safely

from time import perf_counter
def measure(fn, counts, k=10):
    start = perf_counter(); result = fn(counts, k)
    return len(result), perf_counter() - start
# Use synthetic in-memory counts at several bounded e values; save Python/platform.

Use: compare full sort, most_common, and nlargest using identical maps and fixed k. Risk: microbenchmarks include allocation/cache effects and do not benchmark parsing or I/O; do not create a multi-GB lab file. Record results as local observations, then choose from accuracy and memory requirements first.

09 · Safety

sorted(..., key=lambda x: (-x[1], x[0]))

Produce deterministic full rank.Use for auditable ties. Assumes keys are canonical/comparable and exposing them is permitted.

heapq.nlargest(k, iterable, key=...)

Select k candidates.Use with bounded k and an iterable. Validate k is nonnegative and understand memory held by iterable/count map.

Counter.update(stream)

Accumulate exact counts.Use only with cardinality controls/observability; adversarial distinct keys grow state.

Ranking can leak sensitive entitiesTop accounts, IPs, paths, and tokens may be sensitive. Minimize/report pseudonymous identifiers under the right access controls; do not paste raw rankings into public logs or tickets.

10 · Detection scenarios

AUTH

Top failed-login sources

Stream logs to an exact Counter if expected unique IP cardinality fits budget, select top 20 deterministically, and state shared-NAT limitations.

EXFIL

Largest outbound transfers

For top individual transfer events, an O(k) streaming heap is exact and avoids retaining all events; ties need a stable event ID.

PIPELINE

Large log exceeds workstation memory

Do not replace exact aggregation with an unlabeled heap. Use a distributed/external grouping system or explicitly choose a bounded-error heavy-hitter design.

TESTS

Rank report flaps on ties

Add secondary entity ordering and fixture assertions so analysts do not chase meaningless reorderings.
