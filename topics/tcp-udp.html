Networking

Read transport evidence as delivery behavior, not application intent.

TCP is a reliable ordered byte stream built from segments; UDP is connectionless datagrams. Ports and flow tuples identify endpoints in context, not users.

Why it matters

Transport telemetry distinguishes connection attempts, retransmission, resets, and datagrams from application-level success. It is useful context for outages and abuse, not proof of a completed request.

TCP three-way handshake

1  client → server  SYN      seq=1000
2  server → client  SYN,ACK  seq=7000  ack=1001
3  client → server  ACK      seq=1001  ack=7001
4  client → server  50 bytes seq=1001
5  server → client  ACK                ack=1051

This uses illustrative relative numbers: SYN consumes one sequence number, and the ACK value identifies the next byte expected. After 50 payload bytes beginning at 1001, the next expected client byte is 1051. Real captures may display relative or raw sequence numbers and can be affected by capture point/offload. Sequence numbers identify positions in a byte stream; ACKs are cumulative acknowledgments of received bytes. A completed handshake proves both endpoints exchanged transport control packets at the observation point, not that authentication, TLS, or HTTP succeeded.

Reliability and retransmission

TCP orders bytes, detects loss, retransmits, and applies flow/congestion control. Retransmissions can signal loss, reordering, capture loss, or delayed ACKs; do not call them an attack without baseline/context. TCP exposes a byte stream, not message boundaries.

UDP and QUIC

UDP provides datagrams with ports/checksum semantics but no built-in session, ordering, or retransmission guarantee. Applications can add reliability. QUIC runs over UDP and provides encrypted transport/application features for HTTP/3; “UDP” does not mean trivial or automatically unobserved.

The 5-tuple

A common flow key is protocol, source IP, source port, destination IP, destination port. NAT can translate address/port, collectors may see one side only, and reuse over time means add a time window. The curriculum’s 4-tuple usually omits protocol when TCP is implicit.

Teardown and resets

Orderly close is directional: one peer sends FIN, the other ACKs it, and the reverse direction closes with its own FIN/ACK. Like SYN, a FIN consumes one sequence number; half-close is possible while the other direction still sends data. RST abruptly aborts a connection and has no orderly two-direction close. A reset can result from closed ports, application behavior, middleboxes, or timing—not automatically malicious scanning. Capture direction and missing packets matter.

Evidence and safety limits

Use saved/synthetic packets or authorized loopback captures only. Do not scan, flood, or capture shared traffic. Sequence numbers, ports, and packet payloads may be sensitive; sanitize before saving. OS TCP stacks, offloads, and capture points affect what appears in a trace.

Detection scenarios

Login outage

Handshake success with TLS/app failures narrows the fault above transport.

Retransmit spike

Check loss, capture point, and deploy timing before attributing abuse.

UDP service gap

UDP absence may reflect collector visibility or encryption, not no client activity.

RST burst

Correlate endpoint, direction, and application logs; RST has many benign causes.
