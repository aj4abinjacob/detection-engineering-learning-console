01 · Purpose

Why scope matters in production code

Detection code often assembles predicates, enrichers, counters, and callbacks from configuration. A name that resolves differently than expected can route an event to the wrong threshold, erase shared state, or make a test pass only because it accidentally touches a module global.

PREDICTABILITY

Bindings are determined locally

Python decides whether a name is local from the function body, not from which branch happens to execute.

COMPOSITION

Closures carry context

A small function can retain a validated threshold or tenant ID without a global lookup.

TESTING

Ownership is testable

Factory-created state makes test isolation visible; a module global leaks state across tests.

CONCURRENCY

Captured mutable state is shared

A closure is not automatically thread-safe, async-safe, or safe to share across worker processes.

02 · Mental model

Names point to bindings; closures retain cells

LEGB is the usual lookup order: Local, Enclosing function, Global module, then Builtins. Assignment changes the rule: if a function assigns to a name anywhere, Python treats that name as local throughout that function unless declared global or nonlocal.

Lookup is not a data-flow search. A local binding can shadow an outer binding even before the assignment line runs.

03 · Resolution

Assignment is a compile-time declaration of locality

DEFAULT_LIMIT = 10

def bad_limit(use_default: bool) -> int:
    if use_default:
        return DEFAULT_LIMIT  # UnboundLocalError
    DEFAULT_LIMIT = 20        # assignment makes it local everywhere above
    return DEFAULT_LIMIT

In CPython, compile-time symbol-table analysis marks DEFAULT_LIMIT local before the function executes. The first branch therefore reads an uninitialized local, producing UnboundLocalError; it does not fall back to the module name.

global module_name

Rebind a module-global name.Use rarely, mainly for intentional module-level configuration or a controlled singleton. It assumes every caller can safely share and mutate that state; tests, threads, and long-lived services often make that false.

nonlocal enclosing_name

Rebind a binding in the nearest enclosing function scope.Use for deliberately private closure state. It requires the name already exist in an enclosing function—not merely at module scope—and makes the function stateful.

locals(), globals()

Inspect mappings while debugging.Use for observation, not normal control flow. Mutating locals() inside a function is not a reliable way to create local variables, especially across implementations and optimized frames.

def make_counter(start: int = 0):
    count = start
    def increment() -> int:
        nonlocal count
        count += 1
        return count
    return increment

alerts_seen = make_counter()
print(alerts_seen(), alerts_seen())  # 1 2

04 · Enclosing state

A closure stores a reference in a cell, not a frozen snapshot

A nested function that reads a nonlocal name captures a closure cell. You can inspect it for learning with fn.__closure__, but that is an implementation-facing debugging aid—not an interface to mutate.

def make_status_filter(minimum: int):
    def matches(event: dict) -> bool:
        return event["status"] >= minimum
    return matches

server_error = make_status_filter(500)
print(server_error({"status": 503}))  # True
print(server_error.__closure__[0].cell_contents)  # 500

Each call to make_status_filter creates its own minimum cell. If that cell holds a mutable list or dictionary, mutations through any retained reference are visible to all functions sharing that same cell. Prefer immutable configuration values, or pass explicit state through a class/object when lifecycle and synchronization deserve first-class treatment.

05 · Callback trap

Loop-created closures look up the final loop value later

Python closures capture the cell for a name, not its value at function creation. A loop repeatedly updates one cell; callbacks execute after the loop and all observe its final value.

rules = ["login", "checkout", "admin"]
bad = [lambda event: event["route"] == route for route in rules]
print([fn({"route": "login"}) for fn in bad])  # [False, False, False]

# Safe: bind the current value as a default argument at function creation.
good = [lambda event, route=route: event["route"] == route for route in rules]
print([fn({"route": "login"}) for fn in good])  # [True, False, False]
from functools import partial

def has_route(event: dict, route: str) -> bool:
    return event["route"] == route

safe_with_partial = [partial(has_route, route=route) for route in rules]
# A named factory is equally clear:
def make_route_rule(route: str):
    return lambda event: event["route"] == route
Choose clarityDefault arguments are evaluated when the function is created, which is exactly the desired snapshot here. Do not use a mutable default as the snapshot. A named factory is often easier to type-check, log, and explain in a rule engine.

06 · Shared state

Private does not mean synchronized

A closure counter is convenient for a single sequential stream. It is not a durable rate-limit store and does not become safe merely because the name is hidden.

ContextRiskSafer design
ThreadsRead-modify-write operations can interleave; the GIL is not a correctness contract and implementations differ.Use a lock around shared state or a single-owner queue; test the actual concurrency model.
asyncioTasks can interleave at await; a closure may span a long-lived service.Avoid an await between dependent state operations, or guard access with an async lock.
Multiple processes / workersEach process has a separate memory image; counts silently diverge.Use an explicit shared datastore with retention, atomicity, and failure semantics.
Tests / reloadsModule globals survive import caching; counters leak between tests or reset during deploy.Inject state, create it per test, and choose a persistent store when continuity matters.

Version note: LEGB, closure cells, and UnboundLocalError are language-level Python behavior. Exact frame internals, GIL behavior, and scheduling vary across CPython versions and alternative implementations such as PyPy; code correctness should not rely on a particular interpreter’s incidental timing.

08 · On the job

Detection-engineering scenarios

RULES

Route rules all match the last route

A configuration loader creates lambdas in a loop. Add a test with three route values, then bind each route with a factory or default parameter. This is a correctness defect, not a threshold-tuning issue.

TENANT

One tenant’s threshold affects another

A module global is modified while building a request-specific predicate. Capture an immutable validated threshold per factory invocation, or pass a configuration object; log the rule version, not its raw secret-bearing configuration.

RATES

Velocity counts differ between workers

A closure counter lives in each web worker. Its private state is process-local, so the observed count underestimates global activity. Move the detection primitive to a store with explicit atomic increment and TTL semantics.

QA

Tests pass alone but fail together

Find module-global or retained closure state. Construct a fresh analyzer for every test and assert the initial count, rather than resetting unspecified internals after the fact.

09 · Practice

Hands-on drills

1. Draw and prove LEGB

25 min

Save artifacts/scope/legb.py and legb-notes.md. Use the same name in module, outer, and inner scopes, print which binding resolves, then create and explain an UnboundLocalError in a separate function.

  • Label Local, Enclosing, Global, and Builtins in your notes.
  • Point to the assignment that determines locality.
  • State why the exception happens before that assignment executes.

2. Build an isolated closure counter

25 min

Save counter.py and counter-transcript.txt. Create two counters with different starts, invoke them in interleaved order, and inspect their values without using a module global.

  • Use nonlocal correctly.
  • Prove one counter cannot change the other.
  • Describe one case where this in-memory design is not durable enough.

3. Catch and fix a late-bound rule set

30 min

Save a failing late_binding_bad.py, a fixed late_binding_good.py, and rule-matrix.txt showing each rule against each route. Use synthetic route names only.

  • Show why all bad callbacks use the final loop value.
  • Implement two safe fixes and compare readability.
  • Explain why a mutable default would be the wrong fix.
