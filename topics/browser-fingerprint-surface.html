Why it matters

A fingerprint is a set of observed attributes, not a person/device identity. High entropy can improve differentiation while raising privacy cost and still colliding, changing, or being altered by browsers/intermediaries.

Surface inventory

Potential fields include navigator properties, screen geometry/color depth, timezone/locale, rendering APIs, fonts/plugins availability, user agent/client hints, storage/capability signals, and interaction context. Availability differs by browser, permissions, privacy settings, and platform.

Navigator

Examples are language, platform-like hints, hardware concurrency, device memory, webdriver indicator, and capability APIs. Browser vendors reduce/freeze/spoof some values. Missing/altered property is not proof of automation.

Screen and time

Screen dimensions, pixel ratio, color depth, timezone, locale, and clock-related values can vary with monitor, window, travel, settings, remote desktop, accessibility, and privacy controls. Collect only if a declared purpose needs them.

Fonts and plugins

Font availability and plugin APIs are constrained/changed by browsers; probing can be privacy-invasive and unreliable. Treat absence as compatibility/privacy behavior, not a defect or bot signal.

User-Agent and Client Hints

User-Agent is compatibility metadata that can be reduced/frozen. UA Client Hints may require server opt-in and permissions/policy; availability differs. Compare declared values only as low-confidence consistency evidence.

Entropy is distinguishability

Entropy roughly describes how uncommon a value/combo is in a population. It depends on population, collection time, normalization, and correlations; summing field entropy naively overstates uniqueness when fields correlate. More entropy is also more tracking capability.

Stability and collisions

A useful feature must be stable enough for the time horizon and collision-tolerant enough for the decision. Updates, privacy modes, hardware/network changes, shared devices, and deliberate modifications cause drift. Store versions/time and avoid hard identity assertions.

Privacy budget and minimization

Collect minimum fields for stated fraud/security purpose, document notice/consent/legal basis, restrict access/retention, support review, and test false positives. A hash of a fingerprint can remain a stable identifier and is not automatically anonymous.

FingerprintJS educational baseline

Official FingerprintJS repository currently documents v5 migration/import path and calls its open-source client-side library less accurate and vulnerable to spoofing/reverse engineering compared with server-assisted systems. Use v5 as an educational mechanics baseline, not production device-intelligence frontier; record repository/version/license (MIT) when studying it.

Defensive scenarios

Timezone drift

Trigger: changed timezone. Artifact: versioned capability record. Observation: travel/OS update possible. Reasoning: low confidence. Limit: no identity verdict.

UA mismatch

Trigger: hint inconsistency. Artifact: sanitized request/probe schema. Observation: enterprise browser policy. Reasoning: corroborate. Limit: not automation proof.

High-entropy font probe

Trigger: proposed collection. Artifact: data minimization review. Observation: capability exceeds purpose. Reasoning: reject/reduce. Limit: entropy is not need.

Same fingerprint accounts

Trigger: shared value. Artifact: collision/variation note. Observation: shared device/browser. Reasoning: combine account journey. Limit: cannot prove coordination.
