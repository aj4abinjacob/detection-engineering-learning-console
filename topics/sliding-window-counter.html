01 · Purpose

Velocity needs a declared clock

“Five logins in 60 seconds” is not a loop; it is a policy about entity identity, timestamp source, inclusivity, late events, and when idle state disappears.

DETECTION

Per entity

Each key retains only recent event times.

BOUNDARY

Exact semantics

Choose whether an event exactly 60 seconds old counts.

CAPACITY

Bound state

Expired timestamps and idle entities must leave memory.

QUALITY

Order policy

Simple deque expiry assumes arrival/timestamp order.

Every timestamp is appended once and removed once, so expiry work is amortized O(1) per in-order event; the outer map is expected O(1) per entity lookup.

03 · Pick the window

TypeMeaningTrade-off
FixedAnchored interval per key or anchorSimple, but edge effects depend on anchor.
TumblingNon-overlapping global bucketsEasy aggregation; burst across boundary splits.
SlidingEvery event evaluates recent durationMost intuitive velocity signal; retains timestamps.

This guide implements sliding windows using event timestamps. Processing-time windows are simpler but detect ingestion bursts, not necessarily when activity occurred. Record which clock you use and trust its source.

04 · Bounded in-order algorithm

from collections import defaultdict, deque
from datetime import timedelta

class SlidingCounter:
    def __init__(self, window: timedelta, threshold: int) -> None:
        self.window, self.threshold = window, threshold
        self.by_entity: dict[str, deque] = defaultdict(deque)

    def add(self, entity: str, when):
        queue = self.by_entity[entity]
        cutoff = when - self.window
        while queue and queue[0] <= cutoff:  # interval is (cutoff, when]
            queue.popleft()
        queue.append(when)
        return len(queue) >= self.threshold

Use: in-order events with interval semantics (when-window, when]; an event exactly at cutoff is expired. Assumptions: timestamps for each entity arrive nondecreasing and use comparable timezone-aware values. Risk: mixing naive/aware datetimes raises; a late event can leave a newer timestamp at the left and break the expiry loop’s premise.

05 · Ordering and late data

Do not silently pretend out-of-order data is ordered

Choose and document one policy: reject/quarantine late events; use processing time; allow a bounded lateness buffer and reorder before counting; or use a sorted structure at higher cost. The correct policy depends on source guarantees and alert latency. Also decide threshold behavior (alert on every count ≥ threshold, only first crossing, or rate-limit repeats) and test it.

Boundary testFor a 60-second window ending at 12:01:00, this implementation counts timestamps after 12:00:00 through 12:01:00 inclusive. A different interval is valid only if code, detector text, and tests agree.

06 · Bound the outer map too

def expire_idle(self, now):
    cutoff = now - self.window
    for entity, queue in list(self.by_entity.items()):
        while queue and queue[0] <= cutoff: queue.popleft()
        if not queue: del self.by_entity[entity]

Use: periodic cleanup in a controlled scheduler or batch boundary. Assumption: now obeys the same ordering/timezone policy. Risk: scanning all entities is O(e), so schedule it deliberately and cap cardinality; do not run it after every event at high e. A production design may use an expiry index/timer wheel or shard ownership.

07 · Test the detector, not only its code path

from datetime import datetime, timedelta, timezone
t = datetime(2026, 1, 1, tzinfo=timezone.utc)
c = SlidingCounter(timedelta(seconds=60), threshold=3)
assert not c.add("ip", t)
assert not c.add("ip", t + timedelta(seconds=30))
assert not c.add("ip", t + timedelta(seconds=60))  # t is excluded; only two remain
assert c.add("ip", t + timedelta(seconds=61))      # t+30, t+60, t+61 count

Write expected timestamps on paper before coding. Test burst crossing, exactly-at-cutoff, quiet expiry, independent entities, late-event policy, and repeated-alert policy. Tests must use timezone-aware deterministic times, not wall clock.

08 · Safety

deque.popleft()

Expire oldest timestamp.Use only after ordered timestamps are guaranteed; raises IndexError on empty deque, hence the guard.

defaultdict(deque)

Create per-entity queue on first event.Untrusted entity cardinality can allocate indefinitely; enforce limits.

datetime(..., tzinfo=timezone.utc)

Make lab timestamps comparable.Use a documented event-time normalization policy; local clock and parser behavior vary.

Signal, not verdictA velocity threshold can be triggered by NAT, retries, load tests, password-manager sync, or an integration error. Include entity scope, interval, count, timestamp source, and suppression state so an analyst can evaluate it.

09 · Detection scenarios

AUTH

Failed logins from one IP

Count normalized source IP plus tenant over event time, but qualify shared IP/NAT risk and retain a bounded sample for triage.

API

Credential-stuffing burst crosses a minute boundary

A tumbling bucket may split it; a sliding window sees the contiguous burst. Choose deliberate detector semantics.

LATE DATA

Mobile telemetry arrives minutes late

Rejecting it may miss historical correlation; accepting it into an ordered deque may be wrong. Buffer/reorder or label processing-time result.

ABUSE

Random-IP flood causes state pressure

Even one timestamp per unique IP fills the outer map. Set a maximum active entity policy and emit eviction/drop metrics.
