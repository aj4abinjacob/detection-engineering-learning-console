01 · Purpose

Why error behavior is part of a detector

“No alerts” is different from “the parser crashed.” Schedulers, analysts, and downstream systems need that distinction stated through messages, logs, output streams, and exit codes.

TRIAGE

Expected input faults

A malformed record should identify the record and policy, not silently vanish.

RELIABILITY

Defects stay visible

A coding error must not be mislabeled as an empty result.

SAFETY

Users see no secrets

Tracebacks, config paths, tokens, and raw payloads belong only in controlled diagnostics.

AUTOMATION

Status is an API

A stable nonzero outcome lets a job retry, page, or quarantine input appropriately.

02 · Mental model

Catch an exception only where you can recover, add actionable context, or convert it to a boundary contract. Otherwise let it propagate with its traceback for developers.

03 · Catch the narrowest useful type

The hierarchy determines what your handler claims to understand

class AnalyzerError(Exception):
    """Expected, user-correctable analyzer failure."""

class InvalidRecord(AnalyzerError):
    pass

def parse_status(text: str) -> int:
    try:
        return int(text)
    except ValueError as exc:
        raise InvalidRecord("status must be an integer") from exc

Use: a domain exception for expected failures callers can handle consistently. Assumption: the message is safe for the intended audience. Risk: do not erase the cause; chaining preserves the actual parser failure for controlled logs and debugging.

Never use bare except:It catches BaseException, including KeyboardInterrupt, SystemExit, and cancellation-like control flow. except Exception: is still too broad unless a true boundary immediately records and re-raises/returns a safe failure. Catch explicit exceptions you can genuinely handle.

04 · Control flow

else names success; finally names cleanup

def load_rules(path: str) -> dict[str, object]:
    handle = None
    try:
        handle = open(path, encoding="utf-8")
        text = handle.read()
    except FileNotFoundError as exc:
        raise AnalyzerError(f"rule file not found: {path}") from exc
    else:
        return {"bytes": len(text)}  # only runs when try succeeded
    finally:
        if handle is not None:
            handle.close()             # runs after return/exception

Use: else keeps success-only work out of a broad try; finally handles cleanup that must run. Risk: a new exception or a return in finally can mask the original failure. Prefer with open(...) for resources (Topic 3.3).

ClauseRuns whenTypical job
tryAlways firstSmall operation expected to raise a known type.
exceptMatching exceptionRecover, add domain context, or translate.
elseNo exception in trySuccess-only processing.
finallyOn all exitsMinimal cleanup; do not suppress original error.

05 · Preserve causality

Use raise ... from ... to explain layers

def read_json(text: str) -> dict[str, object]:
    import json
    try:
        value = json.loads(text)
    except json.JSONDecodeError as exc:
        raise InvalidRecord("record is not valid JSON") from exc
    if not isinstance(value, dict):
        raise InvalidRecord("record must be a JSON object")
    return value

The displayed chain says what failed at the JSON layer and what it means to this application. Use raise NewError from exc for intentional translation. raise alone reraises unchanged. raise NewError from None suppresses context only when it would be confusing or unsafe to expose; keep internal cause information in protected diagnostics where policy permits.

06 · User-facing behavior

CLI stdout is results; stderr is diagnostics

import sys

def main(argv: list[str] | None = None) -> int:
    try:
        result = analyze(argv)
    except AnalyzerError as exc:
        print(f"error: {exc}", file=sys.stderr)
        return 2       # documented user/input/config failure
    except OSError as exc:
        print(f"error: cannot access input: {exc.strerror}", file=sys.stderr)
        return 3       # documented operational failure
    print(result)      # machine-readable result belongs on stdout
    return 0

if __name__ == "__main__":
    raise SystemExit(main())

Use: choose a small documented exit-code table for your own CLI. Assumption: the caller reads stderr and status. Risk: exit-code conventions vary by tool/platform; do not promise Unix-specific meanings beyond your program’s documentation. Do not display a traceback, a connection string, token, or raw event to a normal user.

07 · Prove the failures

Tests must distinguish expected failure from a bug

def test_bad_status_is_user_error(capsys):
    assert main(["bad-fixture.log"]) == 2
    captured = capsys.readouterr()
    assert "error:" in captured.err
    assert captured.out == ""

def test_programmer_error_is_not_silenced(monkeypatch):
    monkeypatch.setattr("app.analyze", lambda _: 1 / 0)
    # pytest should observe ZeroDivisionError, not a fake empty result

Test a missing file, malformed record, and permission/operational failure using disposable fixtures and platform-appropriate permission setup. Do not rely on permission denial tests while running with elevated privileges; use dependency injection or skip with a reason where the platform cannot produce the condition reliably.

08 · Failure and safety

Handle the contract, not every possible exception

python3 analyzer.py input.log >result.json 2>error.log

Separate output and diagnostics.Use in a local job test. It assumes shell redirection syntax (POSIX); use platform-appropriate equivalents on Windows.

status=$?

Read the previous POSIX-shell status immediately.Use after a command. It is overwritten by the next command; PowerShell and cmd.exe expose status differently.

raise DomainError(...) from exc

Translate with cause.Use at a layer boundary. Ensure the new message does not interpolate secrets from an external exception.

Logging is not an excuse to leakStructured error logs should use a safe event ID, category, and controlled detail. Gate debug tracebacks behind secure configuration and access controls. A malformed event can deliberately contain terminal escapes, huge strings, or credential-like content; bound and sanitize what your error reporter emits.

09 · On the job

Detection-engineering scenarios

INPUT

One corrupt JSON line stops a nightly analysis

Raise InvalidRecord with a safe line number and schema reason, chain the JSON cause for protected debugging, and decide policy: fail the whole batch, quarantine the line, or report a rejected-count metric. Never silently discard it.

SECRETS

A vendor API error includes an authorization URL

Translate the expected operational exception to a message such as “remote lookup failed; see protected run log,” recording a redacted request ID. Printing str(exc) indiscriminately may expose credentials to CI logs or analysts.

DEFECT

A broad handler reports zero findings after a code regression

The catch-all converted a KeyError into success. Narrow the handler to domain/operational exceptions and let the defect fail tests and alert the job owner.

AUTOMATION

A scheduler retries malformed input forever

Give permanent input rejection and transient remote failure different documented codes/categories. The orchestrator’s retry policy can then retry only the latter and route rejected evidence for review.
